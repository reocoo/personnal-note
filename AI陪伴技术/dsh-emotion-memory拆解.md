# dsh-emotion-memory 拆解（0.1.1 实测）

## 二、核心：14 个通道 + 相干矩阵

它不从「情绪词」直接算坐标，中间隔了一层 14 个通道的强度。

14 个锚点取自中科院 PAD 量表（Wang et al. 2023, JAMDSM 17(5) Table 2），原值 ±4 统一除 4 归一化到 −1…1：

| 情绪 | P | A | D |
|---|---|---|---|
| 喜悦 | 0.693 | 0.302 | 0.355 |
| 乐观 | 0.620 | 0.263 | 0.438 |
| 放松 | 0.547 | −0.165 | 0.263 |
| 惊讶 | 0.430 | 0.427 | 0.055 |
| 温和 | 0.393 | −0.198 | 0.095 |
| 依赖 | 0.098 | −0.203 | −0.370 |
| 无聊 | −0.133 | −0.313 | −0.210 |
| 悲伤 | −0.223 | 0.043 | −0.175 |
| 恐惧 | −0.233 | 0.325 | −0.160 |
| 焦虑 | −0.237 | 0.080 | −0.158 |
| 轻蔑 | −0.395 | 0.080 | 0.255 |
| 厌恶 | −0.450 | 0.100 | 0.168 |
| 怨恨 | −0.495 | 0.275 | 0.150 |
| 敌意 | −0.520 | 0.250 | 0.280 |

**注意「悲伤」和「焦虑」的 P 值几乎一样（−0.223 vs −0.237），差别在 A 和 D。** 这正好说明为什么单靠 P 一维不够。

### 相干矩阵

14 个通道之间有传导关系，`W[被影响][影响源]`，正数是拉动，负数是压制。手工写的先验，不是学出来的。摘几条：

```
喜悦 ← 乐观 +0.12、放松 +0.08、悲伤 −0.10
放松 ← 温和 +0.10、焦虑 −0.12、恐惧 −0.10
悲伤 ← 无聊 +0.10、焦虑 +0.08、喜悦 −0.12
焦虑 ← 恐惧 +0.12、怨恨 +0.08、放松 −0.10
敌意 ← 怨恨 +0.12、轻蔑 +0.08、温和 −0.10
```

**这一层的作用是「不让情绪单点跳变」。** 被骂一句，不会只有「敌意」亮起来，怨恨和轻蔑会被一起带起来，温和被压下去。读出来的混合成分才有层次。

### 动力学三件套

| 机制 | 参数 | 干什么 |
|---|---|---|
| 基线回落 | P 0.15 / A −0.10 / D 0.00 | 没有新事件时往这个点回 |
| 弛豫 | P 0.15 / A 0.35 / D 0.20 | 每 5 分钟回 15%~35% |
| 端点收缩 | 余量系数 | 越接近 ±1 步子越小 |

端点收缩是作者踩坑后加的，代码注释写着「之前 P 一直卡在 1.0」。公式：

```js
余量 = 1 - min(1, abs(拉后))
e[k] = 拉后 + Δ[k] * 0.5 * (0.25 + 0.75 * 余量)
```

## 三、派生情绪：它最巧的一块

坐标算出来了，但同一个坐标能有不同含义。它用「通道强度 + 评价条件」合成 9 个派生情绪，条件不满足就打 3 折。

| 派生 | 合成式 | 生效条件 |
|---|---|---|
| 心疼 | 悲伤×0.5 + 温和×0.2 + 依赖×0.2 + 怨恨×0.15 | 指向 = 他人 |
| 吃醋 | 焦虑×0.55 + 敌意×0.35×(1+关系权力×0.5) | 指向 = 被抢 / 他人 |
| 沮丧 | 悲伤×0.5 + 无聊×0.35 | 无条件 |
| 委屈 | 悲伤×0.45 + 怨恨×0.30 + 焦虑×0.15 | 指向 = 自己 且 掌控 < −0.1 |
| 感动 | 温和×0.40 + 喜悦×0.25 + 悲伤×0.15 | 指向 = 他人 且 愿 > 0.15 |
| 愧疚 | 悲伤×0.40 + 焦虑×0.25 + 恐惧×0.15 | 指向 = 自己 且 愿 < −0.1 且 掌控 > 0.1 |
| 释然 | 放松×0.45 + 喜悦×0.25 | 愿 > 0.2 且 意外 > 0.4 |
| 思念 | 温和×0.35 + 悲伤×0.25 + 依赖×0.25 | 指向 = 他人 且 愿 < 0 且 唤醒 < 0.3 |
| 烦躁 | 敌意×0.30 + 焦虑×0.30 + 无聊×0.20 | 唤醒 < 0.4 且 愿 < −0.1 |

**「委屈」和「心疼」的区别只有生效条件不同**：委屈要求「指向自己 + 掌控低」，心疼要求「指向他人」。通道组合几乎一样（都是悲伤打底），但语义完全相反。

这就是 OCC 评价理论在代码里的落点。

## 四、评估器：只填变量，不填坐标

每轮结束调一次模型，`maxTokens: 600`，`temperature: 0.2`，用当前会话的 provider 和 model。

**输出的字段只有这些**：

```
desirability  −1…1   这件事对我好不好
arousal       0…1    它让我多被激起
control       −1…1   这件事里我有多少掌控
unexpected    0…1    意外程度
target        他人 / 未来 / 被抢 / 自己 / ''
关系权力      −1…1   这段关系里我有多少话语权
情绪          14 个里挑一个
reason        一句话，第三人称
confidence    0…100
```

**提示词里明写了反造假规则**：

> 平淡的一轮（只是打招呼、确认、事务性对话）给低分：|desirability| < 0.2、arousal < 0.2、confidence 20~50。
> 别为了显得敏感就编情绪；拿不准就低 confidence。

置信度低于 45 时，`关系权力` 强制归零（不让一个没把握的判断去调制吃醋）。这个细节说明作者想过「模型会瞎猜」这件事。

### 两个防呆

**防呆一：只取真人说的话。**

`judge.js` 里有一个黑名单：

```js
const 注入上下文 = new Set(['runtime-context', 'time-context', 'system-reminder', 'system', 'time-sampled'])
```

注释写着「老的心情插件踩过：把 runtime-context 当成对方说话，每轮都判成没实质内容」。

这跟本机 68 号项目（图片注入复现）查的是同一类坑：harness 往 user 角色里塞机器内容，看起来和人打字完全一样。作者用 `source.kind` 白名单挡掉了。

**防呆二：宿主依赖拿不到也不崩。**

`hostdeps.mjs` 处理 `@deepseek-ai/dsh-tools` 和 `dsh-llm` 的解析。注释里有一段实测记录：

> 桌面版 profile（`autoInstallPeers: false`）永远不装它们 ⇒ 插件整条不激活，DSH 只留一句 `warning: 1 entry did not activate … failed to import`

本机正好是这种情况：`~/.dsh/profiles/desktop/node_modules/@deepseek-ai` 下只有 `cosmokit` 和 `schemastery`，没有 `dsh-tools`、`dsh-llm`。

它的对策是三层：先找宿主树 → 再裸 import → 都失败就用本地等价实现（`localDefineTool` 只补一条 `additionalProperties` 校验）。**兜底那层是「宁可功能降级，不让整条插件不激活」。**

## 五、记忆：指纹、再巩固、四路打分

### 存储位置

落在 `~\.dsh\fish-memory\session-<会话ID>.json`，用的是另一个插件（fish-memory）的目录格式，读 `memories` 数组，只在每条上补一个 `affect` 字段。作者的理由：「记忆只有一份」。

**本机没有这个目录。** 所以装上去是从零开始，不接现有笔记。

### 情感指纹

一条记忆写进去时盖上：

```js
affect: {
  P, A, D,          // 写入时的情绪坐标
  词,                // 写入时的情绪词
  显著性,            // (|A| + |P|) / 2，最低 0.15
  at                // 时间戳
}
```

### 再巩固

被想起来时，用当前状态微调指纹，系数 0.15：

```js
P = 旧P + (当前P - 旧P) * 0.15
```

但**保留写入时的 `词`**，另记 `lastMood`（最近想起时的心情）和 `lastRecallAt`。

注释写着：「不是覆盖——编码时的词保留（那是"当时"），另记"最近想起时"。」

这是对的。记忆被改写但不丢原貌，才叫再巩固，全量覆盖那叫覆盖。

### 四路打分

```
分 = 0.20×新鲜 + 0.15×重要 + 0.60×相关 + 0.05×心境一致
```

| 项 | 算法 |
|---|---|
| 新鲜 | `exp(-天数 / 半衰期)`，半衰期默认 14 天 |
| 重要 | `基础重要度 + log(1 + 被想起次数) × 0.08`，封顶 1 |
| 相关 | 中文二元组重合数 / max(3, 词数×0.35)，**重合少于 2 个直接判 0** |
| 心境一致 | P 同号 +0.7，A 同号 +0.3（各自要过绝对值门槛） |

「重要」里那个 `log(1+hits)` 是 ACT-R 的激活公式。

**ACT-R 是认知科学里一套模拟人脑记忆的理论（Anderson 提出）**，它的核心假设很朴素：一条记忆被提取的次数越多，下次越容易被提取，但这个加成会越来越弱（所以取对数，不是线性叠加）。作者照这个做的。

### 两条硬规矩

```js
if (共 < 2) 相关 = 0        // 只碰上一个二元组当没碰上
if (相关 <= 0) continue      // 完全没共同语言就不想起来，心情像也不行
```

**第二条特别重要**：它拒绝了「心情像就硬想起来」。很多记忆系统会让情绪相似度盖过内容相关度，结果聊天时突然冒出一件八竿子打不着的事。

### 遗忘

```js
if (天 >= 180 && hits === 0 && 重要度 < 0.6) 移进 deleted
```

可恢复，物理不删。每天跑一次。

## 七、结论

**不装。** 三条理由：

1. **每轮多一次模型调用。** judge 输入是双方各 1200 字，输出上限 600 token。本机工程任务为主，这份延迟换不来东西。
2. **记忆这半边比本机现有体系弱。** 字面二元组检索，README 自己写「换说法就漏检」。本机的 AGENTS.md 登记表 + 项目 README 靠读文件，能处理换说法。装了等于开第二个库。
3. **注入的底色会跟人设打架。** `prompt-inject.md` 里的人格是「演完整情绪链」，再挂一个状态机，每轮有第二个源说「精力 42，话要短」。要么无视它（白装），要么被人设被压住。

**什么时候值得装**：要的是长期陪伴聊天，一天几十轮闲话，希望她记得上周的事、会因为被冷落而不高兴。这个包在那条路上是对的设计，而且三项都做齐了（OCC 指向、派生情绪、再巩固）。

**如果只想要「有个情绪状态」**：一个 JSON 文件加一段 prompt-inject 就够，零额外调用。等真需要「她自己想起来」再上包。
