# Nemotron 3.5 Super VL · 一个模型同时看图和读文档

> 原文：**NVIDIA Nemotron 3.5 Super VL Powers Specialized Agents with Multimodal Reasoning**，
> 2026-10-15，作者 Chris Alexiuk、Chintan Patel。
> https://developer.nvidia.com/blog/nvidia-nemotron-3-5-super-vl-powers-specialized-agents-with-multimodal-reasoning/
> **来源等级：读的是原文正文，到「本地优化」一节被截断。** 所有性能数字是 NVIDIA 自己和合作方报的，没有独立复现。
> 模型权重和部分数据集开源（Hugging Face），这是可验证的部分；数字不是。

## 一句话

120B 参数的混合专家模型，每个 token 只激活 12B，把「推理、工具调用、看图读文档看视频」压进一个模型，不用户再拼一个文本模型加一个视觉模型。

## 为什么要有这么一个型号

agent 的工作流变长了：一个请求可能要读文档、跨来源核对、按公司政策判断、调好几个工具。这种活需要三样东西同时在场：**推理、工具调用、多模态理解。**

过去要两个模型接力：文本模型负责想，视觉语言模型负责看。接力就有交接成本：上下文要传过去，两边对任务的理解可能不一致。

他们的卖点是**一个模型里都有**，涵盖的场景：

- 编码：跑测试、读报错、给修复建议
- 网络研究：跨网站搜、把信息连起来、验证答案
- 文档智能：从表格、图表、版面里提信息，出摘要和报告
- 安全：找漏洞、给威胁分优先级
- 视频理解：做检索、内容审查、事件分析

## 分层逻辑（这条最有用）

他们在同一篇里给出了整个家族的定位，说明「什么活用什么模型」：

| 型号 | 干什么 |
|---|---|
| **Nemotron 3.5 Lightning** | 高量的纯文本任务，要快 |
| **Nemotron 3.5 Super VL** | 需要推理 + 工具 + 多模态的多步活，本篇主角 |
| **Nemotron 3 Ultra** | 复杂规划和编排，最重的那档 |

**一个系统里该有几个不同大小的模型，各管一段。** 全部用最大的那个，成本和延迟都不成立。

## 数字与它们各自的含义

| 指标 | 数值 | 怎么读 |
|---|---|---|
| 总参数 / 每 token 激活 | 120B / 12B | MoE，算得省但显存要装全量 |
| agentic 任务吞吐（单 GPU） | 同类开源模型的 5 倍 | Baseten 端点实测，**不是本机** |
| 输出速度 | 600+ tok/s | 同上 |
| CharXiv 图表理解 | 80.8%（对比 Nemotron 3 Nano Omni 63%） | 有 Python 代码解释后到 84% |
| 10,000 任务完成时间 | 快 4 倍 | B200 GPU 上跑，比的是同尺寸开源模型 |

**要点在「任务完成时间」这个指标，不在「tok/s」。** 他们的论点是：对常驻 agent，决定产出的不是单 token 速度，而是**吞吐、token 用量、工具调用次数、纠正一个结果要几步，四样一起**。一个话少但一次做对的模型，比一个快但反复返工的模型强。**这个判据可以直接拿来评价他自己在用的模型。**

## 后训练的收益有多具体

这是全文最实在的部分，三个企业案例：

| 谁 | 干什么 | 结果 |
|---|---|---|
| Scale AI | 给媒体公司做供应商信用处理自动化 | 推理成本降 **40 倍**，延迟降 **5 倍** |
| Ramp | 收据图片转结构化 JSON（商户、日期、付款信息） | 吞吐 **+50%**，延迟降 **10 倍** |
| AI21 + Alice | 威胁情报与漏洞分析 | 准确率 **+41%** |

他们的说法是：这些公司用**自己的**数据、工具、政策、流程做了后训练，所以在自己那摊事上超过了前沿闭源模型。

**这就是「小而专」的完整逻辑链**：开源权重 + 自己的数据 + 后训练 = 在一个窄领域里打赢通用大模型，且便宜一个数量级。

具体手段：NVIDIA NeMo AutoModel 做 SFT（监督微调，拿标注好的输入输出对训练）和 LoRA（低秩适配，只训练一小部分附加参数，省显存）；NeMo RL 做强化学习；NeMo Gym 提供环境做评测。数据方面在 Hugging Face 放了 40 个视觉语言数据集，加上工具调用、金融推理、长上下文等数据集。

## 对老大的意义

**1. 解释了他免费额度里那一堆 nemotron 型号。**
`nano` / `super` / `ultra` / `omni` 不是营销命名，是分层：小的跑量，中的跑多模态多步，大的做规划。**选型判据是「这一步要不要推理和看图」，不是「哪个听起来强」。**

**2. 「120B 只激活 12B」这个设计，是他能用免费 API 的原因之一。**
MoE 把「模型能知道多少」和「每次推理花多少」拆开了。代价是显存（见 [02-GLM-5.3](02-GLM-5.3-双机vLLM.md) 那篇：稀疏激活不省显存）。

**3. 后训练这件事他做不了，但可以记结论。**
训练一个 120B 模型要几十张卡。他能做的是**理解为什么别人能做到**：不是模型更强，是数据更对口。反过来也提醒他：**他自己的 agent 效果不好时，先问数据对不对口，别急着换模型。**

**4. 最可能翻车的地方。**
这些数字全部来自厂商自己的评测集和合作方自述。40 倍成本下降是「这个特定工作负载 + 这个特定量化 + 这个特定部署」的组合结果，换场景不成立。**当一个方向感可以，当承诺不行。**
