# AI 记忆与 dreaming：从「它记不住」到「它造的东西会留下」

> 这份笔记的目的：**让你能对一个完全没接触过这个领域的人讲明白**，同时自己复习时能拿回全部细节。
>
> 所有数字来自 2026-11-08 ~ 11-09 对本机的实测，方法在文末。没有转述。
>
> 配套项目：`86-Dreaming记忆维护\`。配套前作：`AI记忆系统-本机实现与可实行措施.md`（那份讲四条通道，这份讲怎么用它们做 dreaming）。

---

## 开篇：先破除一个幻觉

### 「AI 记不住」这句话是错的

说「AI 记不住」，隐含一个前提：有一个「它」在，只是记性差。

**实际不是。** 大模型每次被调用时，它拿到的只有一段文字（上下文窗口里的内容）。它没有过去，没有昨天，没有「上次我们聊到哪」。**窗口里没有的东西，对它来说不存在。**

所以准确的说法不是「它忘了」，而是——**每次对话都是一次全新的开始，而某些之前的文字被放进来了。**

这个区别很重要。因为如果问题是「记性差」，解法是「加强记忆」；如果问题是「没有连续性，只能靠外部材料喂」，解法完全不同：**你得在窗口外面存东西，然后在下次开始之前喂进去。**

整个 dreaming 系统做的就是这么一件事。

### 一个类比（讲给别人听时用这个）

把一个新会话想成一个**失忆症患者每天早上醒来**。

- 他智力正常，能推理、能干活、能学新东西
- 但他不记得昨天
- 床边可以放纸条

那我们能做的事就很清楚了：

| 要解决的问题 | 办法 |
|---|---|
| 他今天该怎么说话、怎么判断 | 放一张**每天固定摆在床头的卡**（每轮注入） |
| 昨天具体发生了什么 | 放一个**抽屉，他要用时自己去翻**（按需检索） |
| 谁来写这些纸条 | 得有个**晚上的整理流程**（dreaming） |

**这三件事就是全部。** 剩下的都是工程细节。

## 一、窗口外面能存什么：只有两类

这是整个设计的地基。想清这一层，后面都顺。

### 判据只有一句：不做任何事，它花不花你的预算？

| 类别 | 特征 | 代价 | 举例 |
|---|---|---|---|
| **常驻类** | 每轮都要在窗口里，不做任何事也占着 | 每轮都付费，而且会**挤掉别的东西** | 我是谁、怎么说话、七条铁律 |
| **检索类** | 不主动查就不存在 | 零常驻成本，但**你得知道去查** | 上次那个 bug 怎么修的、磁盘还剩多少 |

本机实测的数字（2026-11-09）：

```
人格文件 prompt-inject.md        34,241 B   每轮注入
工作区 AGENTS.md                 29,501 B   每轮注入
技能索引（129 条 description）   约 42,000 B  每轮注入
─────────────────────────────────────────────
每轮固定花掉                    约 105 KB
```

**这就是为什么不能什么都塞进去。** 每轮预算有限，塞满了会静默截断——
2026-10-28 实测过：登记表塞得太满，注入被截到 64,428 字节，尾部整段丢失，**而且不报错**。

**静默截断比报错危险一万倍**，因为你以为它在，其实不在。

### 于是分成两层的判据

| 层 | 装什么 | 判据 | 错了会怎样 |
|---|---|---|---|
| **偏好层** | 我是什么样、怎么说话、怎么判断 | 「这是**他是什么样的人**」或「我该怎么干活」 | **每一句话都受影响** |
| **事实层** | 命令原文 + 原始输出 | 「这条**有命令能重放**」 | 只是证据过期，可查可推翻 |

**注意两条判据的形式不一样**：偏好层问的是「关于谁」，事实层问的是「能不能验证」。
这不是随意定的，是因为两层的失效代价完全不同——见第四节。

## 二、为什么需要 dreaming：模型不会自己记

### 一个反直觉的事实

模型**在对话中**可以记住东西——因为它还在同一个窗口里。
但**对话一结束，窗口清空，什么都没留下。**

它不会「顺手把今天的收获存下来」，因为「存下来」需要写文件，而写文件这个动作必须发生在会话里、必须有人让它做。

### 所以必须有个批处理

这就是 dreaming 的定位：**在会话之外，定期把当天发生过的事整理成下一天能用的材料。**

名字借的是神经科学里的「记忆巩固」（memory consolidation）：白天经历的事先暂时存着，睡眠时被重新激活、筛选、写进长期记忆。

**这里的关键是「筛选」**：不是把一天所有话都抄一遍，而是挑出「值得留下的」。

### 本机实现的五个阶段

```
① 机械档扫描      查日期过期 / 死链 / 事实冲突    2 秒     纯读，最便宜，先跑
② 事实 wiki 验证  重放各页的验证命令              15 秒    给下一步提供「今天验证过什么」
③ 生成 digest     把当天会话压成摘要              3 秒     下一步的输入
④ 偏好抽取        headless agent 抽偏好候选       80~110 秒
⑤ 事实抽取        headless agent 抽事实候选       140~210 秒
```

**顺序不能变**，每个阶段的输出是下一个的输入。

整轮 4~6 分钟。每阶段跑完立刻写状态文件，**中途 Ctrl-C 不丢已完成的记录**。

### 一个关键设计：抽取交给独立的 headless agent

为什么不用主会话自己抽？

**因为主会话的上下文已经很满**（人格 + 工作区手册 + 技能索引 + 一整天的对话）。
再让它读 40 万字的原始会话，既贵又容易漏。

所以：**先把一天 1.6 MB 的会话压成 200~400 KB 的摘要，再派一个上下文干净的 agent 去抽。**

这个 agent 用 `dsh headless` 起，配置在 `tools/dreaming-agent.yml`，三件事：

1. **工具裁到 6 个**（edit / glob / grep / read / read_image / write）——它只干一件事，给它 27 个工具是浪费也是干扰
2. **禁用会话持久化**——否则每跑一次留一个 65 KB 的会话文件，一年 700 个，还会污染检索
3. **禁 dsh-purge**——无人值守不需要人格注入

## 三、最难的部分：怎么保证写进去的是真的

这一节是整份笔记的核心。**因为假记忆比没记忆更糟。**

### 「假记忆」长什么样

2026-11-09 我抓到过三种：

**第一种：假成功。**
抽取任务报「✓ 完成 106 秒」，产物文件也在、大小也对——但那个文件是**两小时前的旧文件**，
这次根本没写成功（写权限被挡在外面）。

判据是 `文件存在 and 大小 > 200`，对它完全成立。

**第二种：编造的 raw。**
我在对话里给事实层举格式样例，配了「共 329 个包，0 处命中 / 耗时 8.2 秒」。
那是**设计讨论时编的**，不是跑出来的。但读起来和专业实测记录一模一样。

**抽取出这件事的是事实抽取 agent，它原话**：

> 摘要里 232 条命令全部被统一截断到约 200 字符，断口处不给省略号。
> 所以命令原文在摘要里本身就不是完整可重放物。
> **我没有替任何一条补全——补全等于我编命令。**

**第三种：结论跑在证据前面。**
我对外说「**找到了！** 这 350 字符单独发就会被拒」，
但紧跟着的三条实测**全是 PASS**，而且数量对不上（350 vs 63）。

同一个 agent 标了「未验证」，并写：

> 在拿到那一次真跑之前，不能把「找到触发点了」当已解决写进任何地方。

### 三条防线

#### 防线一：raw 原则 —— 存命令，不存结论

```
❌ 「网络通了」
✅ 「跑 Invoke-WebRequest 得到 200，耗时 1000ms」
```

**为什么**：结论会被照抄，命令才能被验证。
六个月后，前一句无法复查，后一句重跑一次就知道还对不对。

本机的实现是 `~/.dsh/fact-wiki/`，一主题一页，每页按「验证 #N」叠加：

```markdown
## 2026-11-09 · 验证 #2

**验证方式**
    <能原样重放的完整命令>

**原始输出**
    <真实跑出来的原文>

**这次读出来的**
    <只写命令能支持的那部分>

**这次没验证的**
    <明确标出>
```

#### 防线二：叠加不覆盖 —— 差异可以共存

同一条命令跑两次结果不同，怎么办？

**不是「哪个对」的问题，是两条记录并存。**

| 情况 | 做法 |
|---|---|
| 结果相同 | 次数 +1，刷新验证日期，不新增记录 |
| 结果不同 | **在顶层追加新记录**，带上新的验证方式 |
| 旧记录 | **原样保留，不标「已推翻」** |

老大的原话：「保留原文，不标状态，差异可以存在，也许有无法控制的变量，默认先验证新的，如果发现问题，就当是维护记忆了。」

**为什么这样**：差异往往不是「有一个错了」，而是「变量没控制住」。
标成「已推翻」等于假装我们知道哪个对，而实际上我们不知道。

#### 防线三：交叉验证 —— 不信单一来源

「上次更新是什么时候」这个问题，状态文件会记，但**记录可能和实际不符**。

所以本机的做法是：状态记录 + 产物实际 mtime，两边对比。

```
产物比记录新  →  提示「状态记录落后于产物」
有产物无记录  →  提示「有产物但无成功记录」
```

同理，抽取阶段的判据是 **mtime 必须变新**，不是「文件存在」。
这一条就是被第一种假成功逼出来的。

### 还有一个容易忽略的：谁在说话

会话日志里 `user` 角色装的东西，**远不止用户打的字**：

| 看起来像用户说的 | 实际是什么 |
|---|---|
| `<system-reminder>` | harness 塞的工作区指令 |
| `Current runtime context` / `Time sampled while preparing` | 运行时注脚 |
| `<available_skills>` | 技能目录 |
| `Attached image(s) from tool result:` | 工具返回带图时合成的消息 |
| `You are a dreaming agent...` | **我自己派子代理时写的任务说明** |

**这个坑真实存在**：本机有 60 个带图片工具结果的会话，其中 17 个出现「突然不知道要干什么、重新问一遍已经答过的问题」。
不带图片的 462 个里只有 2 个。

所以抽取前必须过滤。本机实现里有一串 `MACHINE` 特征串，
并且**按行过滤**——因为注脚常和真话在**同一条消息**里。

## 四、两层的失效代价为什么不同

这一点值得单独讲，因为它决定了「谁能自动改、谁不能」。

### 偏好层的错，会放大到每一句话

偏好层是**每轮注入**的。里面写错一句，接下来每一轮我都带着这个错说话。

举例：如果偏好层写「老大喜欢简洁」，但实际他要详细步骤，那我每一次回答都会错，
而且**错得理直气壮**——因为那是「我的人格」的一部分。

所以偏好层的改动有个闸门：**先判断环境，再决定要不要覆盖。**

### 事实层的错，只是一个数据点坏了

事实层不进上下文，只在主动查的时候才读。
一条记录错了，影响的是「查那一次」，而且 raw 原则保证了你可以重跑命令发现它错了。

所以事实层可以用机械规则自动更新：跑命令、比结果、计数或追加。

### 于是有了这条规矩

> **dreaming 可以直接修改偏好，但是不能修改事实，只能迭代。**

这句话的准确含义不是「技术上不能」，而是**「判断类的改动风险太高，必须有人过一遍」**。

本机的实现：dreaming 跑完产出**候选**（`proposals/`），不是直接改生产文件。
采纳与否由人决定。

## 五、本机实际长什么样（可核对）

### 三条注入通道

2026-11-09 查清的结构：

| 通道 | 文件 | 机制 | 体量 |
|---|---|---|---|
| **systemPrompt** | `~/.dsh/prompt-inject.md` | `dsh-purge` 插件读它注入 | 34,241 B |
| **home 级作业指令** | `~/.dsh/AGENTS.md` | `dsh-agent-instructions`，以 `<system-reminder>` 注入 | 4,619 B |
| **工作区作业指令** | `DSH工作区\AGENTS.md` | 同上 | 29,501 B |

**关键事实**：DSH 内置的注入只认四个文件名——
`AGENTS.md` / `CLAUDE.md` / `AGENTS.local.md` / `CLAUDE.local.md`。

**所以**：叫 `REGISTRY.md`、`NOTES.md` 的内容，写得再重要也不会被自动读。
想让内容退出常驻，把它从这四个名字下搬走就行。

### 两条命令，随时核对

```powershell
# 看 dreaming 状态（上次更新、五阶段结果、频率）
python "86-Dreaming记忆维护\tools\dream_state.py"

# 按关键词查记忆库（三层都搜）
python "86-Dreaming记忆维护\tools\memory_query.py" "关键词"
```

### 图形化：终端记忆管理器

```powershell
# Windows Terminal 下拉菜单第 2 项「记忆管理器」
# 或
cd "86-Dreaming记忆维护\tools" ; python memory_tui.py
```

四个栏目：

```
1 偏好层    可勾选。☑ 已启用 / ☐ 已勾掉 / ▪ 核心段锁定不可勾
2 事实wiki  只读。每页按「验证 #N」分条
3 digests   只读。每天一个文件，每场会话一段
4 dreaming  按 d 跑一轮，按 f 调频率，显示上次更新时间
```

**核心段锁定**的意思是：删掉它我就不再是 Mo，或者删掉会破坏文件结构。
比如 `# Mo`、七条铁律、执行内核。

## 六、哪里会翻车（诚实的边界）

### 已知会失效的情况

**一、headless 的写权限 = 当前工作目录。**
`sandbox-policy.workspaceRoot = process.cwd()`，**只有 cwd 及其子目录可写**。
用 `cwd=tools` 启动，agent 想写 `proposals\` 会被拒，而且三次提权都返回
`requires approval, but no approval channel is available`。

**修法**：cwd 用项目根。

**二、Windows 计划任务装不了。**
`schtasks /create` 返回 `Access is denied`（本机无管理员权限）。
自动触发只能走「启动文件夹」：`tools\setup-autostart.ps1 -Mode daily`。

**三、effort 参数可能被中间层吃掉。**
本机实测：`magpie` 会把 DSH 的 thinking 钉成 `high`，而且只认 `web` profile。
在别的 profile 写 `reasoningEffort` **会被覆盖**——
表现为 high 和 low 测出来方向是反的（440 vs 685）。

**修法**：直连 provider，绕开那层。

**四、短题测不出思考量差异。**
同一道题单次采样的方差，比两档之间的差异还大。
本机实测第一次报「7.51 倍」，重测各 3 次变成 high=[477,332,369] / low=[283,661,335]。
**换成必须分三小问作答的长题才稳定。**

### 我明确标「未探测」的

- **注入是否足以导致漂移**：本机没测出来（68 号那批实验仪器坏了），不等于已证伪
- **AI97 中转认不认 `reasoning_effort`**：间接证据有，没做单变量对照
- **TUI 按键的真实手感**：从 pwsh 工具里跑没有真实 console buffer，只能验渲染和按键注册

## 七、怎么讲给别人听

### 三分钟版（讲给完全外行）

> 大模型没有记忆。每次对话对它来说都是全新的开始，它只能看到这次对话窗口里的文字。
>
> 所以想要「它记得」，只能做两件事：
> 一是**把必须知道的东西每次开场都摆出来**（比如「你是这样说话的一个助手」）；
> 二是**把其他东西存起来，需要时去查**（比如「上次那个 bug 怎么修的」）。
>
> 但这两件事都得有人写。模型自己不会在夜里悄悄记录。
> 所以就有一个额外的流程：定期把发生过的事整理成材料，挑出值得留的，写成上面那两种。
>
> 这流程有个麻烦——**写错了比不写还糟**。所以规矩是：只存原始证据（命令和输出），不存结论；
> 结果变了就两条都留着，不假装知道哪个对；每次写入都要能复查。

### 十分钟版（讲给同行）

在上面基础上加四层：

1. **为什么分层**：常驻的每轮都花预算，而且会静默截断；检索的零常驻但要主动查。
   两层的判据不同——偏好层问「关于谁」，事实层问「能不能验证」。
2. **为什么抽取要独立 agent**：主会话上下文已满，再读原始日志既贵又漏。
   先压成摘要（1.6 MB → 300 KB），再派干净上下文的 agent 抽。
3. **三条防线**：raw 原则（存命令不存结论）、叠加不覆盖（差异共存）、交叉验证（状态 + mtime）。
4. **失效代价不对称**：偏好层的错会放大到每一句话，所以只出候选不自动改；
   事实层的错只是一个数据点，可以机械更新。

### 讲的时候别做的事

- **别说「它记住了」**。要说「上次写的材料这次被读进来了」。前者是幻觉，后者是真的。
- **别把类比当解释**。床头纸条那个类比只解释结构，不解释技术。
  一旦对方问「那纸条怎么保证不是假的」，就得切回真实机制。
- **别夸大成「像人一样有记忆」**。这套东西的本质是**外部材料管理**，
  不是「模型内部有了记忆」。这个区别决定了所有设计取舍。

---

## 八、一句话总结

> **模型没有记忆，但它造的东西会留下。**
> 留下的东西必须能复查，所以只存原始证据；
> 复查的时候必须承认自己会错，所以差异共存、不装懂。
> dreaming 就是那个「在会话之外，把一天整理成下一天能用的材料」的流程。

### ⚠️ 一条关于「旧判据会过期」的提醒

2026-11-09 复跑全部验收脚本时发现：**`test_l1.py` 的两条判据现在报 FAIL，但这不是 bug。**

| 判据 | 为什么现在不过 |
|---|---|
| A3 注入不涨 | L8（拆偏好层）和 L12（写底气）合法地增加了内容，34,241 B > 当时的基线 33,452 B |
| A2 偏好留存 | 当时那个标题叫 `# 二、老大的处境`，L8 改名成了 `# 二、他的约束 → 我的默认做法` |

**这说明一件事**：判据是**当时那个快照**的证据，不是永远成立的真理。
历史阶段的验收脚本会随着后续改动而失效，这是正常的。

**要不要修它们？** 不修。理由：修了等于抹掉「当时是什么样」的记录。
正确的读法是——**跑 L 阶段的脚本是「复现当时那次验收」，不是「检查现在对不对」**。
