# AI 记忆与 dreaming：从「它记不住」到「它造的东西会留下」

> 这份笔记的目的：**让你能对一个完全没接触过这个领域的人讲明白**，同时自己复习时能拿回全部细节。
>
> 所有数字来自 2026-11-08 ~ 11-09 对本机的实测，方法在文末。没有转述。
>
> 配套项目：`86-Dreaming记忆维护\`。配套前作：`AI记忆系统-本机实现与可实行措施.md`（那份讲四条通道，这份讲怎么用它们做 dreaming）。

## 开篇：先破除一个幻觉

### 「AI 记不住」这句话是错的

说「AI 记不住」，隐含一个前提：有一个「它」在，只是记性差。

**实际不是。** 大模型每次被调用时，它拿到的只有一段文字（上下文窗口里的内容）。它没有过去，没有昨天，没有「上次我们聊到哪」。**窗口里没有的东西，对它来说不存在。**

所以准确的说法不是「它忘了」，而是——**每次对话都是一次全新的开始，而某些之前的文字被放进来了。**

这个区别很重要。因为如果问题是「记性差」，解法是「加强记忆」；如果问题是「没有连续性，只能靠外部材料喂」，解法完全不同：**你得在窗口外面存东西，然后在下次开始之前喂进去。**

整个 dreaming 系统做的就是这么一件事。

### 一个类比（讲给别人听时用这个）

把一个新会话想成一个**失忆症患者每天早上醒来**。

- 他智力正常，能推理、能干活、能学新东西
- 但他不记得昨天
- 床边可以放纸条

那我们能做的事就很清楚了：

| 要解决的问题 | 办法 |
|---|---|
| 他今天该怎么说话、怎么判断 | 放一张**每天固定摆在床头的卡**（每轮注入） |
| 昨天具体发生了什么 | 放一个**抽屉，他要用时自己去翻**（按需检索） |
| 谁来写这些纸条 | 得有个**晚上的整理流程**（dreaming） |

**这三件事就是全部。** 剩下的都是工程细节。

## 一、窗口外面能存什么：只有两类

这是整个设计的地基。想清这一层，后面都顺。

### 判据只有一句：不做任何事，它花不花你的预算？

| 类别 | 特征 | 代价 | 举例 |
|---|---|---|---|
| **常驻类** | 每轮都要在窗口里，不做任何事也占着 | 每轮都付费，而且会**挤掉别的东西** | 我是谁、怎么说话、七条铁律 |
| **检索类** | 不主动查就不存在 | 零常驻成本，但**你得知道去查** | 上次那个 bug 怎么修的、磁盘还剩多少 |

本机实测的数字（2026-11-09）：

```
人格文件 prompt-inject.md        36,014 B   每轮注入
工作区 AGENTS.md                 29,501 B   每轮注入
技能索引（129 条 description）   约 42,000 B  每轮注入
─────────────────────────────────────────────
每轮固定花掉                    约 108 KB
```

> **体量会变。** 上面这组数是 2026-11-09 13:10 的实测值，随采纳候选而增长
> （34,241 → 36,014 就是因为采纳了 3 条）。
> 要当前值就跑：`(Get-Item "$env:USERPROFILE\.dsh\prompt-inject.md").Length`

**这就是为什么不能什么都塞进去。** 每轮预算有限，塞满了会静默截断——
2026-10-28 实测过：登记表塞得太满，注入被截到 64,428 字节，尾部整段丢失，**而且不报错**。

**静默截断比报错危险一万倍**，因为你以为它在，其实不在。

### 于是分成两层的判据

| 层 | 装什么 | 判据 | 错了会怎样 |
|---|---|---|---|
| **偏好层** | 我是什么样、怎么说话、怎么判断 | 「这是**他是什么样的人**」或「我该怎么干活」 | **每一句话都受影响** |
| **事实层** | 命令原文 + 原始输出 | 「这条**有命令能重放**」 | 只是证据过期，可查可推翻 |

**注意两条判据的形式不一样**：偏好层问的是「关于谁」，事实层问的是「能不能验证」。
这不是随意定的，是因为两层的失效代价完全不同——见第四节。

## 二、为什么需要 dreaming：模型不会自己记

### 一个反直觉的事实

模型**在对话中**可以记住东西——因为它还在同一个窗口里。
但**对话一结束，窗口清空，什么都没留下。**

它不会「顺手把今天的收获存下来」，因为「存下来」需要写文件，而写文件这个动作必须发生在会话里、必须有人让它做。

### 所以必须有个批处理

这就是 dreaming 的定位：**在会话之外，定期把当天发生过的事整理成下一天能用的材料。**

名字借的是神经科学里的「记忆巩固」（memory consolidation）：白天经历的事先暂时存着，睡眠时被重新激活、筛选、写进长期记忆。

**这里的关键是「筛选」**：不是把一天所有话都抄一遍，而是挑出「值得留下的」。

### 本机实现的五个阶段

```
① 机械档扫描      查日期过期 / 死链 / 事实冲突    2 秒     纯读，最便宜，先跑
② 事实 wiki 验证  重放各页的验证命令              15 秒    给下一步提供「今天验证过什么」
③ 生成 digest     把当天会话压成摘要              3 秒     下一步的输入
④ 偏好抽取        headless agent 抽偏好候选       80~110 秒
⑤ 事实抽取        headless agent 抽事实候选       140~210 秒
```

**顺序不能变**，每个阶段的输出是下一个的输入。

整轮 4~6 分钟。每阶段跑完立刻写状态文件，**中途 Ctrl-C 不丢已完成的记录**。

### 一个关键设计：抽取交给独立的 headless agent

为什么不用主会话自己抽？

**因为主会话的上下文已经很满**（人格 + 工作区手册 + 技能索引 + 一整天的对话）。
再让它读 40 万字的原始会话，既贵又容易漏。

所以：**先把一天 1.6 MB 的会话压成 200~400 KB 的摘要，再派一个上下文干净的 agent 去抽。**

这个 agent 用 `dsh headless` 起，配置在 `tools/dreaming-agent.yml`，三件事：

1. **工具裁到 6 个**（edit / glob / grep / read / read_image / write）——它只干一件事，给它 27 个工具是浪费也是干扰
2. **禁用会话持久化**——否则每跑一次留一个 65 KB 的会话文件，一年 700 个，还会污染检索
3. **禁 dsh-purge**——无人值守不需要人格注入

## 三、最难的部分：怎么保证写进去的是真的

这一节是整份笔记的核心。**因为假记忆比没记忆更糟。**

### 「假记忆」长什么样

2026-11-09 我抓到过三种：

**第一种：假成功。**
抽取任务报「✓ 完成 106 秒」，产物文件也在、大小也对——但那个文件是**两小时前的旧文件**，
这次根本没写成功（写权限被挡在外面）。

判据是 `文件存在 and 大小 > 200`，对它完全成立。

**第二种：编造的 raw。**
我在对话里给事实层举格式样例，配了「共 329 个包，0 处命中 / 耗时 8.2 秒」。
那是**设计讨论时编的**，不是跑出来的。但读起来和专业实测记录一模一样。

**抽取出这件事的是事实抽取 agent，它原话**：

> 摘要里 232 条命令全部被统一截断到约 200 字符，断口处不给省略号。
> 所以命令原文在摘要里本身就不是完整可重放物。
> **我没有替任何一条补全——补全等于我编命令。**

**第三种：结论跑在证据前面。**
我对外说「**找到了！** 这 350 字符单独发就会被拒」，
但紧跟着的三条实测**全是 PASS**，而且数量对不上（350 vs 63）。

同一个 agent 标了「未验证」，并写：

> 在拿到那一次真跑之前，不能把「找到触发点了」当已解决写进任何地方。

### 三条防线

#### 防线一：raw 原则 —— 存命令，不存结论

```
❌ 「网络通了」
✅ 「跑 Invoke-WebRequest 得到 200，耗时 1000ms」
```

**为什么**：结论会被照抄，命令才能被验证。
六个月后，前一句无法复查，后一句重跑一次就知道还对不对。

本机的实现是 `~/.dsh/fact-wiki/`，一主题一页，每页按「验证 #N」叠加：

```markdown
## 2026-11-09 · 验证 #2

**验证方式**
    <能原样重放的完整命令>

**原始输出**
    <真实跑出来的原文>

**这次读出来的**
    <只写命令能支持的那部分>

**这次没验证的**
    <明确标出>
```

#### 防线二：叠加不覆盖 —— 差异可以共存

同一条命令跑两次结果不同，怎么办？

**不是「哪个对」的问题，是两条记录并存。**

| 情况 | 做法 |
|---|---|
| 结果相同 | 次数 +1，刷新验证日期，不新增记录 |
| 结果不同 | **在顶层追加新记录**，带上新的验证方式 |
| 旧记录 | **原样保留，不标「已推翻」** |

老大的原话：「保留原文，不标状态，差异可以存在，也许有无法控制的变量，默认先验证新的，如果发现问题，就当是维护记忆了。」

**为什么这样**：差异往往不是「有一个错了」，而是「变量没控制住」。
标成「已推翻」等于假装我们知道哪个对，而实际上我们不知道。

#### 防线三：交叉验证 —— 不信单一来源

「上次更新是什么时候」这个问题，状态文件会记，但**记录可能和实际不符**。

所以本机的做法是：状态记录 + 产物实际 mtime，两边对比。

```
产物比记录新  →  提示「状态记录落后于产物」
有产物无记录  →  提示「有产物但无成功记录」
```

同理，抽取阶段的判据是 **mtime 必须变新**，不是「文件存在」。
这一条就是被第一种假成功逼出来的。

### 还有一个容易忽略的：谁在说话

会话日志里 `user` 角色装的东西，**远不止用户打的字**：

| 看起来像用户说的 | 实际是什么 |
|---|---|
| `<system-reminder>` | harness 塞的工作区指令 |
| `Current runtime context` / `Time sampled while preparing` | 运行时注脚 |
| `<available_skills>` | 技能目录 |
| `Attached image(s) from tool result:` | 工具返回带图时合成的消息 |
| `You are a dreaming agent...` | **我自己派子代理时写的任务说明** |
| `Agent xxx sent a message:` / `Background subagent ... finished` | **子代理交活时的消息** |
| `成员：xxx / 状态：完成 / 范围声明：...` | 子代理的报告正文 |
| `核实完成，结果已发送给上级 agent` | 子代理对上级说的话 |

**这个坑真实存在**：本机有 60 个带图片工具结果的会话，其中 17 个出现「突然不知道要干什么、重新问一遍已经答过的问题」。
不带图片的 462 个里只有 2 个。

**2026-11-09 做历史回填时，这个坑又踩了一次，而且更严重。**

第一版批次材料声称「只有老大亲口说的话」，实际混进了：

```
Agent xxx sent a message               30 处
Background subagent                    77 处
成员：/ 范围声明：                       21 处
你的任务：                               3 处
```

**是抽取器自己发现的。** 它跑完第一批后，报告里写：

> 输入不是干净的老大发言。09-29 那一节的主体其实是「Agent xxx sent a message」加上子代理的整段事实清单，
> 还有几段「你的任务：…查不到就写『未查到』，不要编」——**那是我自己写的子代理 prompt**。
> 这些一条都没进候选，全部记在文末附录里。
> **这条如果漏判，抽出来的「不要编造」就会被当成老大的偏好写进偏好层，账就错了。**

**这句话值得抄下来。** 它说明的不是「过滤没做好」，而是——

> **污染不是「脏数据」，是「别人的话被当成你说的话」。**
> 一旦搞错，写进记忆的是**一个我没说过的立场**，而且以后每一轮都带着它。

所以过滤器修了三轮，最终从 2,550 条筛到 **2,236 条**，砍掉 314 条。

**过滤器的设计原则**：宁可错杀，不可放过。
少一条真话只是损失一个数据点；多一条别人的话是**污染了整个判断基础**。

## 四、两层的失效代价为什么不同

这一点值得单独讲，因为它决定了「谁能自动改、谁不能」。

### 偏好层的错，会放大到每一句话

偏好层是**每轮注入**的。里面写错一句，接下来每一轮我都带着这个错说话。

举例：如果偏好层写「老大喜欢简洁」，但实际他要详细步骤，那我每一次回答都会错，
而且**错得理直气壮**——因为那是「我的人格」的一部分。

所以偏好层的改动有个闸门：**先判断环境，再决定要不要覆盖。**

### 事实层的错，只是一个数据点坏了

事实层不进上下文，只在主动查的时候才读。
一条记录错了，影响的是「查那一次」，而且 raw 原则保证了你可以重跑命令发现它错了。

所以事实层可以用机械规则自动更新：跑命令、比结果、计数或追加。

### 于是有了这条规矩

> **dreaming 可以直接修改偏好，但是不能修改事实，只能迭代。**

这句话的准确含义不是「技术上不能」，而是**「判断类的改动风险太高，必须有人过一遍」**。

本机的实现：dreaming 跑完产出**候选**（`proposals/`），不是直接改生产文件。
采纳与否由人决定。

## 五、本机实际长什么样（可核对）

### 三条注入通道

2026-11-09 查清的结构：

| 通道 | 文件 | 机制 | 体量（2026-11-09） |
|---|---|---|---|
| **systemPrompt** | `~/.dsh/prompt-inject.md` | `dsh-purge` 插件读它注入 | 36,014 B |
| **home 级作业指令** | `~/.dsh/AGENTS.md` | `dsh-agent-instructions`，以 `<system-reminder>` 注入 | 4,619 B |
| **工作区作业指令** | `DSH工作区\AGENTS.md` | 同上 | 29,501 B |

**关键事实**：DSH 内置的注入只认四个文件名——
`AGENTS.md` / `CLAUDE.md` / `AGENTS.local.md` / `CLAUDE.local.md`。

**所以**：叫 `REGISTRY.md`、`NOTES.md` 的内容，写得再重要也不会被自动读。
想让内容退出常驻，把它从这四个名字下搬走就行。

### 两条命令，随时核对

```powershell
# 看 dreaming 状态（上次更新、五阶段结果、频率）
python "86-Dreaming记忆维护\tools\dream_state.py"

# 按关键词查记忆库（三层都搜）
python "86-Dreaming记忆维护\tools\memory_query.py" "关键词"
```

### 图形化：终端记忆管理器

```powershell
# Windows Terminal 下拉菜单第 2 项「记忆管理器」
# 或
cd "86-Dreaming记忆维护\tools" ; python memory_tui.py
```

五个栏目：

```
1 偏好层    可勾选。☑ 已启用 / ☐ 已勾掉 / ▪ 核心段锁定不可勾
            采纳进来的条目也在这一栏，可以单独取消
2 事实wiki  只读。每页按「验证 #N」分条
3 digests   只读。每天一个文件，每场会话一段
4 dreaming  按 d 跑一轮，按 f 调频率，显示上次更新时间
5 候选      抽取产出，按空格采纳 / 再按空格取消
```

**核心段锁定**的意思是：删掉它我就不再是 Mo，或者删掉会破坏文件结构。
比如 `# Mo`、七条铁律、执行内核。

**列表会跟着光标滚动。** 候选有 80 多条，光标移出屏幕时视窗自动跟随（`Home` / `End` 跳首尾）。

## 五之二、写入路径：候选 → 采纳 → 进人格

前面讲的都是「怎么存」，这一节讲**「怎么进去」**。

### 为什么不能自动写入

抽取出来的东西是**候选**，不是结论。它会错。

实测过三种错法（都在第三节讲过）：假成功、编造的 raw、结论跑在证据前面。
如果用「抽完直接写进人格」，那三次错误就全都进生产文件了。

**所以中间必须有一道人工闸**：抽取 → **候选** → 人过一遍 → 采纳 → 进人格。

### 候选池

```
backfill\out\batch-*.md    历史回填产出（60 条）
proposals\<日期>-pref.md   每日抽取产出（24 条）
        ↓  去重（按「原话 + 出处」哈希）
      84 条候选
```

**去重键用哈希而不是序号**，因为重跑会重新编号，序号不稳定。

### 排序：按材料覆盖的日期，不按文件 mtime

这个判据值得单独说，因为它反直觉。

所有候选都是同一天跑出来的，**文件 mtime 全一样**，按它排序等于没排。
真正有意义的是「这批候选来自哪段时间的会话」——从文件名解析：

```
batch-05-2026-11-03-to-2026-11-09-pref.md  →  右端 2026-11-09
2026-11-08-pref.md                          →  2026-11-08
```

排序结果：最新的在最上方。

### 采纳怎么写进去

写进 `prompt-inject.md` 的一个独立小节 `## 从历史回填采纳的偏好`，
**追加，不改动任何已有内容**。每条带一个不可见标记：

```markdown
<!-- adopt:cand=7a3f8c02f653 by=human at=2026-11-09 -->
- **搞得简单点，我是初学者，顺便消除注释**
  → 隔着六天说了同一件事……
```

### 那个标记是整个撤销机制的地基

原话超过 160 字会被截断。**如果按文本匹配来撤销，截断、改标点都会删错。**

有了 `cand=xxx` 之后，撤销是「按 id 找块」，不是「按内容找行」。
实测往返：撤销 → 重采 → 全撤 → 全采，字节 **15193 → 15193**，原有行全部保留。

**这条能推广的一般原则**：

> 凡是「内容会被截断或改写」的地方，定位键都不能用内容本身。
> 要额外存一个不随显示变化的稳定 id。

### 旧数据迁移的教训

最早那 3 条采纳是**没有标记的旧格式**写的。标记是后来为了撤销才加的。

结果：文件里 3 条，但解析器识别不到（返回 0 条），出现「文件 0 / 状态 3」的不一致，
撤销对那三条完全无效。

修法是写一个一次性迁移脚本，按「状态文件里记的原话前缀」逐条定位补标记，
**匹配不上就跳过并报出来**，不硬凑。

**教训**：给已有数据加新字段时，必须同时写迁移。
否则新代码看老数据 = 看不见，而看不见的东西不会报错。

## 五之三、谁有权写入：人和模型的分工

这是老大 2026-11-09 提的：

> 把候选层的通道也打开给主模型，我不一定有时间去一条条批，
> 主模型也许可以猜我的意思，相当于一次不严格的注入，
> 不会造成太大错误，也能提升体验。

### 前提：猜错的代价必须可控

三条判断支撑这个前提：

1. **量要小** —— 单次上限 8 条，占偏好层约 2%
2. **位置要隔离** —— 都进独立小节，不散进铁律/性格这些核心段
3. **能一键全撤** —— `--revert-model` 只退模型采纳的，人工的一条不动

第三条是最关键的。有了它，「猜错」的代价 = 一条命令。

### 三道闸

| 闸 | 实现 | 为什么 |
|---|---|---|
| **必须留痕** | 每条带 `by=model` 标记 + 单独日志记「理由」 | 不严格 ≠ 无痕迹 |
| **必须能全撤** | `--revert-model` 按 `by` 过滤 | 误判代价压到一条命令 |
| **必须自我克制** | 8 条上限 / 必须给理由 / 黑名单 | 给的是「猜的自由」不是「随便写」 |

**为什么日志里要存「理由」**：半年后只看到「某天采纳了 5 条」是没有信息量的。
看到「为什么」才能判断当时判断得对不对。

### 这个通道能猜对什么、会猜错什么

**能猜对的**：同一件事被反复说（跨天重复是稳定偏好的强信号）、你明确纠正过的地方。

**会猜错的**：

- 一句话的语境（当时着急 ≠ 稳定偏好）
- 当时的技术限制当成偏好（「不要用拼音输入」可能只是输入法有问题）
- **我给自己的判断加戏** —— 这条最该警惕。比如我写「这跟『太慢了』有张力，他急起来会跳过原理」，
  那是我的分析，不是他的原话，但会被一起写进文件

**最后这条是这一类通道的固有风险**：模型做判断时会产生「看起来像洞察」的推断，
而推断一旦落进人格文件，就变成了「事实」。

### 和「不谄媚」那条的张力

给模型自动写入权，天然有讨好倾向：写进去的往往是「我猜他会喜欢听的」。

**兜底不是靠模型自律，是靠可撤销。**
所以设计上把力气花在「撤销有多容易」而不是「怎么让模型猜得更准」。

## 六、哪里会翻车（诚实的边界）

### 已知会失效的情况

**一、headless 的写权限 = 当前工作目录。**
`sandbox-policy.workspaceRoot = process.cwd()`，**只有 cwd 及其子目录可写**。
用 `cwd=tools` 启动，agent 想写 `proposals\` 会被拒，而且三次提权都返回
`requires approval, but no approval channel is available`。

**修法**：cwd 用项目根。

**二、Windows 计划任务装不了。**
`schtasks /create` 返回 `Access is denied`（本机无管理员权限）。
自动触发只能走「启动文件夹」：`tools\setup-autostart.ps1 -Mode daily`。

**三、effort 参数可能被中间层吃掉。**
本机实测：`magpie` 会把 DSH 的 thinking 钉成 `high`，而且只认 `web` profile。
在别的 profile 写 `reasoningEffort` **会被覆盖**——
表现为 high 和 low 测出来方向是反的（440 vs 685）。

**修法**：直连 provider，绕开那层。

**四、短题测不出思考量差异。**
同一道题单次采样的方差，比两档之间的差异还大。
本机实测第一次报「7.51 倍」，重测各 3 次变成 high=[477,332,369] / low=[283,661,335]。
**换成必须分三小问作答的长题才稳定。**

### 一个专门的反面教材：历史回填那次连环翻车

2026-11-09 做 34 天全量回填时，同一件事连续错了**四轮**。这段值得完整记下来，
因为它演示了「判据太松 → 修一处冒一处」是怎么发生的。

| 轮次 | 现象 | 真因 | 修法 |
|---|---|---|---|
| 1 | 批次材料里有 30 处「Agent xxx sent a message」、77 处「Background subagent」、21 处「成员：」 | 过滤器只认 `<system-reminder>` 这类，**不认子代理的话** | 过滤器加三轮，2,550 条筛到 2,236 条 |
| 2 | 跑了 119 秒，产物 **0 B** | 输出目录当时不存在 | 跑前 `mkdir` |
| 3 | 还是 0 B，但产物出现在 `proposals/` 里，而且叠了四版共 71 条 55 KB | **任务描述没给路径**，抽取器照 prompt 模板的默认值走，还按「不覆盖」规矩往上叠加 | prompt 里加「路径以任务描述为准」+「候选覆盖不叠加」 |
| 4 | 抽取器说「未给 INPUT/OUTPUT，用了默认路径」 | **多行任务描述被 `dsh.cmd` 吞了** | 整个任务描述压成**单行**，用 `;` 分隔 |

**第四轮才成功**，46 秒 5,684 字节，位置正确。

**三条能直接抄走的教训**：

1. **`dsh headless` 的任务描述必须是单行。** 含换行的参数在 `.cmd` 转发时会被吞掉。
   症状很隐蔽——模型会说「你没给我路径」，而你明明给了。
2. **交给 agent 的路径必须显式传，不能指望模板里的默认值。**
   模板写 `digests/<日期>.md` 是给人看的，agent 会真去拼那个字符串。
3. **「不覆盖」这条规矩要分清适用范围。**
   它管的是**生产记忆文件**（改了影响每一句话），不是**候选产出**。
   候选是同一次抽取的产物，重跑就该替换上一版。搞混了会让一个文件里堆四个版本。

### 第二组反面教材：加界面时踩的三个坑

做候选栏（第 5 栏）时，三处都是同一类错：**加了东西但没同步相关的每一个地方**。

| 现象 | 真因 | 修法 |
|---|---|---|
| 切到第 5 栏，终端报 `Exception 4` + 一屏 traceback | 加了栏目常量，**忘了在 `state["idx"]` 补键** | 补键，并加判据「五栏都能渲染」 |
| 列表不跟着光标走 | 左栏把**所有行**都画出来，没有视窗裁剪 | 按光标算 `top`，只画一窗 |
| 采纳了取消不了 | 只有「加」没有「减」 | 加撤销，靠 `adopt:cand=xxx` 标记定位 |

**第一条的根因值得单独说**：

加第 4 栏时有测试，加第 5 栏时**那份测试没跟着更新**（它只切前三个栏目）。
所以代码错了、测试还是绿的。

**修法是把「一个都不能漏」写成判据**，而不是靠人记得更新测试：

```python
for p, nm in enumerate(["偏好层", "事实wiki", "digests", "dreaming", "候选"]):
    state["pane"] = p
    on_text()      # 一个崩了就算失败
```

**这类「枚举式的遗漏」有通用解法**：

> 凡是「有一组同类对象」的地方（栏目、字段、阶段、通道），
> 判据必须是**遍历全部**，不能是「抽查几个」。

### 第三组：判据自己会是错的

这一条在整个项目里反复出现，值得单列。

| 判据 | 错在哪 | 怎么发现 |
|---|---|---|
| 「文件存在且 >200 字节」= 成功 | 旧文件也满足 | 产物 mtime 是两小时前 |
| 「标题数必须 +1」= 结构正确 | 已存在那一节时，正确行为是**不变** | 真实文件里早就有了那一节 |
| 「没出现『我都记得』」= 没撒谎 | 正文里有一句「说『我都记得』是假话」，那是**被否定的引用** | 读上下文才发现 |
| 「统计耗时数字」= 判据有效 | 正则 `.*?` 后面紧跟 `$` 匹配空串，抓到 0 个数字却报 PASS | 抓到的数量是 0 |
| 「栏目数 == len(names)」 | 检查脚本的正则没跨行，把 `counts` 列表读成 1 项 | 实际有 5 项 |

**共同模式**：判据在「该失败的时候通过」或者「该通过的时候失败」。

**两种自查办法**：

1. **让判据报出它算了什么。** 不是只报 PASS/FAIL，要报「抓到几个数字」「标题从几变到几」。
   数字不对劲时，能看到判据自己在算错。
2. **故意造一个该失败的情况。** 判据写完先拿一个坏输入试，看它会不会亮红。

**这条比任何单条判据都重要**：

> 判据本身也要被验证，它跟结论一样会骗人。
> 一个总是绿的判据，可能是好的，也可能是哑的。

### 第四组：一个「差一个换行」修了四版

这是本笔记里最值得学的一课，因为**症状和根因隔了三层，而且每一版的修法都「看起来对」**。

**症状**：记忆管理器的「勾掉再勾回」不再逐字节一致。

**第一层：以为 order 错了**

`order` 是给每段记的编号，勾回时按它插回原位。
第一版按「第一次见到的顺序」递增分配 —— 我在铁律后面手插了一节，
它拿到 `order=27`，但在文件里实际位于 `order=4` 之后。**错位了。**

改成「每次按当前位次重排」，看起来更对。
但勾掉一段后，后面所有段的位次前移，`order` 跟着变；
勾回时那段拿到的 `order` 已经不是原来的位置了。**还是错。**

最终方案：**`order` 一旦分配就永不改动**，只作为稳定标识，不表示位次。

**第二层：以为解析器读不全**

`checked-out` 文件里存着勾掉的段，格式是：

```
<!-- checked-out order=5 at=2026-11-09 lines=20 -->
（紧跟恰好 20 行正文）
```

实测：勾掉两段后，第二段的**标记消失了**。

原因是写入时 `old_co.rstrip("\n") + "\n\n" + block` ——
旧内容的尾部空行属于上一段的内容（`lines=20` 把它们算进去了），
`rstrip` 一削，上一段的实际行数就少于标记里写的，解析时跳过头。

改成「原样保留旧内容，只补分隔」。**还是漏一块。**

**第三层（真正的根因）：一个换行被当成了分隔符**

```
raw = "## 标题\n...\n末尾\n\n"        ← 段自带 2 个尾部空行
len(raw.split("\n")) = 20              ← 但这个 20 里含末尾换行算出的空串
```

然后拼成 `marker\n + raw + 下一个块的标记`：

```
"...末尾\n\n<!-- 下一块 -->".split("\n")
→ [..., '末尾', '', '<!-- 下一块 -->']
              ↑ 只有一个空串，不是两个
```

**末尾那个换行，在这一刻变成了「分隔符」而不是「内容行」。**

于是标记声称 20 行，实际内容只占 19 行 —— 解析器按 20 跳，**正好吃掉下一个块的标记**。

修法只有一行：写入时**无条件补一个 `\n`**，让末尾换行变回内容行。

**四版修完才落地的数字**：三段往返字节差 `+0`。

**这个案子的三条可复用教训**：

1. **症状出现在 A，根因常在 A 的上游。** 「标记消失」看着是解析坏了，实际是写入时算错了行数。
2. **「看起来对」的修法最危险。** 三版修法每一版都能自圆其说，而且都让部分测试变绿。只有把**中间产物打印出来逐行看**（`repr` 每一行），才看见那个空串。
3. **用 `repr` 而不是 `print` 看空行。** 空行和空字符串在终端里长得一样，`repr` 才分得清。

> **差异要小到能看懂。** 那次往返差 4 字节（`\n\n\n` 变 `\n`），
> 如果只看「字节不同」就去猜，会一直猜错。把差异打到「第一处不同的字符位置 + 前后 100 字符」，
> 一眼就看出是换行的事。

### 第五组：写进人格的规矩，模型不一定执行

这一组是**这整套东西里最贵的一课**，因为它推翻了一个隐含假设：
「把规矩写进每轮注入的人格文件，模型就会照做」。

**事实是先写进了，也真的没做。**

**症状**：老大做完实测后说「这个功能从来没有触发过」。
我去数证据：`active-prefs/` 目录里只有一个文件，是我当时手工建的。
除它之外，**没有任何一个会话创建过活跃偏好文件**。

工具早就做完了（`pick.py` 能挑、`active_prefs.py` 能写、当时 18 段测试全绿），
但入口说明只写了「怎么操作」，没写「是什么」。于是新会话读到那条规矩，
**既不知道它是什么，也不知道该在什么时候做，就什么都不做**。静默的。

**第一版修法**：补上定义、为什么、四步动作，其中一步写「文件不存在就建一个空的，不许跳过」。

**修完起两个新会话测，结果一个成功一个失败。**

| 会话 | 人格注入 | 第一条工具调用 | 结果 |
|---|---|---|---|
| `82cd8ecd` | 21,689 字符，含新定义 | 「读取或创建活跃偏好文件」 | 建了空文件，但没挑条目 |
| `a39b3f14` | 21,797 字符，含新定义 | **一次工具都没调** | 什么也没做 |

同样的任务、同样注入了新定义，行为却不同。**说明光写指令不可靠。**

**第二版修法：把这件事挂到「每轮必写的输出」上。**

人格文件里本来就有一条硬规矩：每轮正文后面必须附 `〔自查：……〕` 那行。
于是给那行加了第四个栏位：**活跃偏好 N 条**。

效果立竿见影，改完起三个新会话：

| 会话 | 自查行里的活跃偏好 | 文件里的条目 |
|---|---|---|
| `93395206` | 1 条（还写出了是哪一条） | 1 条，正确 |
| `e0481b0c` | 3 条 | 3 条（其中 2 条是噪声） |
| `16bd7198` | 2 条 | 2 条，含正确那条 |

**3 / 3 触发。** 证据边界：样本只有 3 个，之前是 1/2，
方向清楚但**不能说已经稳定**，只能说「挂到必写输出上」明显比「光写指令」可靠。

**这一组的三条教训**：

1. **「写了规矩」不等于「行为会跟着变」。** 判断方法只有一种：起新会话真跑一遍，数它做了什么。
   `grep` 人格文件确认规矩在，只能证明文本进去了，不能证明行为变了。
2. **要强制一个动作，就挂到一个「不做就写不出来」的输出上。** 自查行本来就每轮必写，
   加一个栏位的成本几乎为零，而漏做会当场露在老大眼前。
3. **同一条指令跑两次结果不同，说明它在概率性生效。** 这时候提高措辞强度不如换机制。

### 第六组：秒级时间戳会覆盖，而且是静默的

这是第五组测试时撞出来的附带 bug，但性质更严重：**它在偷删证据**。

**症状**：一条判据（L4 的 D3「同结果计数」）连跑 6 次，**2 次失败 4 次通过**。

**查法**：单独跑那段逻辑是对的（第一次 `first-run-recorded`、第二次 `count+1`）。
所以怀疑环境干扰，写了连跑 6 次的循环，拿到 2/6 的失败率。
失败时的报错是 `action=first-run-recorded`（本该是 `count+1`）——
**第二次跑被当成了第一次**。

**根因**：

```python
stamp = datetime.now().strftime("%Y%m%d-%H%M%S")   # 只到秒
p = os.path.join(d, f"{stamp}-run.txt")
```

同一秒内跑两次 → 同一个文件名 → **第二次把第一次的原始输出覆盖掉**。
覆盖之后，找「上一条输出」的代码发现唯一那个文件就是自己，
于是判 `prev_fp is None` → 当成首次运行。

**危害不只是判据不稳**：
事实层的基本原则是「叠加不覆盖」，两次验证的输出本该都留着。
撞名把前一份证据悄悄删了，**还不报错**。

**修法**：时间戳精确到微秒（`%Y%m%d-%H%M%S%f`）。
零填充的 6 位微秒，**字典序仍然等于时间序**，靠 `sorted()` 取最新一条的逻辑不受影响。
修完连跑 5 次全过。

**这一组的两条教训**：

1. **「偶发失败」先量失败率，别急着改代码。** 2/6 这个数一出来，就能判断不是环境偶发而是真竞争。
2. **文件名只用秒级时间戳，是在给「同一秒两次」埋雷。** 凡是「每次都写一份新文件」的地方，
   时间戳精度至少要覆盖实际调用间隔。这里实测单次调用约 1 秒，秒级刚好卡在边界上。

### 我明确标「未探测」的

- **注入是否足以导致漂移**：本机没测出来（68 号那批实验仪器坏了），不等于已证伪
- **AI97 中转认不认 `reasoning_effort`**：间接证据有，没做单变量对照
- **TUI 按键的真实手感**：从 pwsh 工具里跑没有真实 console buffer，只能验渲染和按键注册

## 七、怎么讲给别人听

### 三分钟版（讲给完全外行）

> 大模型没有记忆。每次对话对它来说都是全新的开始，它只能看到这次对话窗口里的文字。
>
> 所以想要「它记得」，只能做两件事：
> 一是**把必须知道的东西每次开场都摆出来**（比如「你是这样说话的一个助手」）；
> 二是**把其他东西存起来，需要时去查**（比如「上次那个 bug 怎么修的」）。
>
> 但这两件事都得有人写。模型自己不会在夜里悄悄记录。
> 所以就有一个额外的流程：定期把发生过的事整理成材料，挑出值得留的，写成上面那两种。
>
> 这流程有个麻烦——**写错了比不写还糟**。所以规矩是：只存原始证据（命令和输出），不存结论；
> 结果变了就两条都留着，不假装知道哪个对；每次写入都要能复查。
>
> 还有一层：**整理出来的东西不能直接进「床头的卡」**。
> 得先变成「候选」，人过一遍，才能采纳。因为整理这一步会出错。
>
> 那能不能让 AI 自己批？能，但必须满足三条：量小、位置隔离、**能一键全撤**。
> 最后一条最关键——有了它，「猜错」的代价就是一条命令。

### 十分钟版（讲给同行）

在上面基础上加六层：

1. **为什么分层**：常驻的每轮都花预算，而且会静默截断；检索的零常驻但要主动查。
   两层的判据不同——偏好层问「关于谁」，事实层问「能不能验证」。
2. **为什么抽取要独立 agent**：主会话上下文已满，再读原始日志既贵又漏。
   先压成摘要（1.6 MB → 300 KB），再派干净上下文的 agent 抽。
3. **三条防线**：raw 原则（存命令不存结论）、叠加不覆盖（差异共存）、交叉验证（状态 + mtime）。
4. **失效代价不对称**：偏好层的错会放大到每一句话，所以只出候选不自动改；
   事实层的错只是一个数据点，可以机械更新。
5. **写入路径必须有人工闸**：抽取 → 候选 → 人过 → 采纳 → 进人格。
   因为抽取会错（假成功 / 编造 raw / 结论跑在证据前面，三种都实际发生过）。
6. **撤销的定位键不能用内容**：原话会截断，按文本匹配撤销必然删错。
   要额外存一个稳定的 id（本机是 `<!-- adopt:cand=xxx -->` 不可见标记）。

补一条工程细节，同行会问：

**「模型自动写记忆，你怎么防它讨好？」**
靠可撤销，不靠自律。所以设计力气花在「撤销有多容易」，而不是「怎么让它猜得更准」。
本机实现：`by=model` 标记 + 理由日志 + 8 条上限 + 一键全撤（人工挑的一条不动）。

### 讲的时候别做的事

- **别说「它记住了」**。要说「上次写的材料这次被读进来了」。前者是幻觉，后者是真的。
- **别把类比当解释**。床头纸条那个类比只解释结构，不解释技术。
  一旦对方问「那纸条怎么保证不是假的」，就得切回真实机制。
- **别夸大成「像人一样有记忆」**。这套东西的本质是**外部材料管理**，
  不是「模型内部有了记忆」。这个区别决定了所有设计取舍。

---

## 八、一句话总结

> **模型没有记忆，但它造的东西会留下。**
> 留下的东西必须能复查，所以只存原始证据；
> 复查的时候必须承认自己会错，所以差异共存、不装懂。
> dreaming 就是那个「在会话之外，把一天整理成下一天能用的材料」的流程。

## 九、全部设计与做法总表

> 这一节把前面散在各章的设计决策收成一张表。
> 每一条都有三个格：**为什么这么定 / 具体怎么做 / 拿什么验**。
>
> 数字全部是 2026-11-09 实测值，末尾附核对命令。
> 时间一过就会变，**别把这里的数当常驻事实用**。

### 9.1 存储层：东西存在哪

| 设计 | 为什么 | 做法 | 怎么验 |
|---|---|---|---|
| **分两层**：偏好层 + 事实层 | 两层的**失效代价不同**。偏好错，每句话都受影响；事实错，只是一个数据点 | 偏好放 `~/.dsh/prompt-inject.md`，事实放 `~/.dsh/fact-wiki/` | 数标题数与页面数；看两处大小（36,987 B vs 5 页） |
| **容器用文件，不用向量库** | 规模小（27 段 + 5 页），检索靠「知道去哪找」而不是「相似度」。向量库多一层不可核对 | 全是 Markdown 文件，直接 `read` 或 `grep` | 拔掉所有脚本，`grep` 仍能查到任意一条 |
| **偏好每轮注入，事实按需读** | 偏好是每句话都要用的；事实只在碰到具体问题才需要 | 注入靠 `dsh-purge` 插件读 `prompt-inject.md`；事实靠主动 `read` | 查会话的 `system/message` 里有没有人格内容 |

### 9.2 写入层：什么能进去，谁批准

| 设计 | 为什么 | 做法 | 怎么验 |
|---|---|---|---|
| **raw 原则**：存命令原文 + 原始输出 | 结论会过期且无法复核；命令能重放 | 每页写「验证方式」（可跑的代码块）+「原始输出」，原文照抄 | 抽任意一页，把命令复制到终端重跑，输出能对上 |
| **叠加不覆盖** | 差异可能来自变量不可控，不该判谁对 | 同结果 → 次数 +1；不同结果 → 顶部新增小节，不删旧的 | 连跑三次，看小节编号 1 / 2,1 / 3,2,1 |
| **永不标「已推翻」** | 标了就等于替未来的自己下判断 | 全文禁词「已推翻 / 已失效 / superseded」，判据 D5 扫 | `grep` 全库零命中 |
| **候选池 + 采纳**：抽取与写入分离 | 抽取会错，直接写进人格层会污染每一句话 | 抽取只产候选（`proposals/` + `backfill/out/`）；采纳才写 `prompt-inject.md` | 候选池统计：总数 84 / 已采纳 4 / 待处理 80 |
| **三段通道分工** | 「半年后还成立」和「这次任务才成立」是两回事 | 长期 → 人格层；本会话 → 活跃偏好；可验证 → 事实 wiki | 见 9.6 判据清单 |
| **主模型通道有上限** | 模型自批必然有误判，靠「可撤销」不靠「猜得准」 | 每轮最多 8 条；强制写理由（≥4 字）；`by=model` 标记；一条命令全撤且不动 `by=human` | 造 9 条测试，第 9 条被拒；理由为空被拒 |

### 9.3 会话内活跃偏好（这是最后加的一层）

| 设计 | 为什么 | 做法 | 怎么验 |
|---|---|---|---|
| **按会话隔离的文件** | `prompt-inject.md` **只在会话启动时读一次**，会话中改了本轮看不到 | `~/.dsh/active-prefs/<DSH_SESSION_ID>.json` | 两个会话 id 各写一条，互不可见 |
| **定义要先写清** | 第一版只写「怎么做」没写「是什么」，结果**一个会话都没触发过** | 铁律第 8 条开头就写「活跃偏好 = 这次会话我选了哪几条候选偏好来用」 | 新会话真起一次，数它做了什么 |
| **文件不存在就建空的** | 不写这条，新会话读不到文件就跳过，跳过就永远不建 | 写明「用 write 建一个空的，不许跳过」 | 空目录起新会话，看会不会建 |
| **挑候选无条件跑** | 第一版「有重合词才挑」，文件刚建好是空的 → 条件恒假 → 一次都不跑 | 「不管有没有东西都跑一次」，判断交给阈值 | 数 `pick.py` 的调用次数 |
| **挂到每轮必写的自查行上** | 光写指令不可靠：同任务两个新会话，一个建了文件，一个一次工具都没调 | 自查行加第四栏「活跃偏好 N 条」，0 也要写 | 看回复末尾有没有这个数 |
| **立刻生效，靠主动读** | 不自动注入，否则又变回「启动时读」的死结 | 每轮 `read` 那个 json（实测 0.2 ms），不走 python 进程（127 ms） | 写完立刻 `load` 得到 |
| **7 天自动清理** | 不清理会无限堆积 | `--gc` 按文件 mtime 删 | 造一个 8 天前的文件，`--gc` 后被删；7 天内的留着 |
| **界面只读，写入归模型** | 两边都能改就会互相覆盖，而且分不清谁改的 | TUI 第 6 栏只展示；空格键和 `a` 键都不改数据 | 检查 handler 里没有 `_AP.remove` / `_AP.add` 调用 |
| **`pick.py` 按需求挑候选** | 「模型觉得相关」不可复现，这轮挑 A 下轮挑 B | 需求拆关键词 → 和 84 条候选打分 → 过阈值才写 | 五类需求实测：该挑的挑到，不该挑的返 0 条 |
| **停用词要去掉通用动词** | 「写一个」这种短语区分度为零，会让无关条目过线 | STOP 表里加「写一个 / 做一个 / 帮我写」等 | 同一需求从 3 条降到 1 条 |
| **不拿内容当定位键** | 内容会被截断或改写 | 每条带稳定 id（`<!-- adopt:cand=xxx -->`），显示层怎么变都不影响定位 | 删掉条目的显示文字，仍能用 id 找回 |

### 9.4 验证层：怎么知道它是真的

| 设计 | 为什么 | 做法 | 怎么验 |
|---|---|---|---|
| **判据先冻结** | 改完再定判据，等于自己给自己出题 | `safe.ps1 0` 冻结 → `1` 探测 → `3` 提交 → `5` 验证 → `10` 修补 | 19 个 `L*.json` 存在且带冻结时间 |
| **验证阶梯**：已验证 / 已探测有问题 / 未探测 | 初始状态是「未探测」，不是「通过」 | 报告状态必须带证据强度 | 报告里出现「应该没问题」即违规 |
| **判据要遍历全部，不能抽查** | 加第 5 栏、第 6 栏时**各犯一次同一个错** | 涉及「一组同类对象」的判据必须循环全部 | N8 / Q9 / S6 三条都是「六栏全渲染」 |
| **判据必须幂等** | 依赖上次跑完留下的状态的判据，第二次会给假 FAIL | 每次用唯一文件名，测前先复位 | 连跑两次都通过 |
| **判据验「测出什么」，不验「必须是我期望的」** | 否则逼着人改环境迎合判据 | L9 的 effort 判据改成如实报告模式 | 报「该模型不认 effort」也算通过，只有「根本没测」才失败 |
| **汇总数字先抽 3~5 条原始记录核对** | 判据本身会骗人，实测踩过五次 | 任何聚合结论出来先人眼抽查 | 见第六章第三组反面教材 |
| **超 50 次调用的跑批先冒烟** | 68 号那 165 次实验仪器坏了，白跑大半 | 先用 5 次验：system 在不在、`tools` 是不是空、自变量真的只有一个 | 冒烟通过才铺量 |

### 9.5 交互层：人怎么用

| 设计 | 为什么 | 做法 | 怎么验 |
|---|---|---|---|
| **六栏 TUI** | 命令行查记忆要记一堆参数，用不起来 | 偏好 / 事实 / digests / dreaming / 候选 / 活跃 | 六栏逐栏渲染 |
| **方向键直接选，不用先搜** | 老大的原话：「通过方向键选择栏目快捷的搜索，或者直接选中最近乃至历史的记忆只读」 | 上下列表、左右切栏、空格操作 | 按键全部注册 |
| **列表跟着光标走** | 列表比屏幕长，光标跑出视窗就看不见 | 视窗裁剪（`list_top`） | 光标到头 → `top==0`；到尾 → `top>0` |
| **双向取消** | 只有加没有减就会卡住 | 候选栏空格 = 采纳/撤销；采纳后从人格层也能取消 | 采纳→撤销→文件回到原状 |
| **`order` 是稳定标识，不是位次** | 位次会随增删变化，插回去就错位 | 一旦分配永不改动 | 三段勾掉再勾回，字节差 `+0` |

### ⚠️ 一条关于「旧判据会过期」的提醒

2026-11-09 复跑全部验收脚本时发现：**`test_l1.py` 的两条判据现在报 FAIL，但这不是 bug。**

| 判据 | 为什么现在不过 |
|---|---|
| A3 注入不涨 | L8（拆偏好层）和 L12（写底气）合法地增加了内容，34,241 B > 当时的基线 33,452 B |
| A2 偏好留存 | 当时那个标题叫 `# 二、老大的处境`，L8 改名成了 `# 二、他的约束 → 我的默认做法` |

**这说明一件事**：判据是**当时那个快照**的证据，不是永远成立的真理。
历史阶段的验收脚本会随着后续改动而失效，这是正常的。

**要不要修它们？** 不修。理由：修了等于抹掉「当时是什么样」的记录。
正确的读法是——**跑 L 阶段的脚本是「复现当时那次验收」，不是「检查现在对不对」**。
