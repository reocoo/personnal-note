# 公司里人怎么协作，以及它跟多智能体哪里像、哪里不像

> 材料来源：八项经典理论与实证，每一项都标了证据档次（强 / 中 / 通识）。
> 三档的意思是：**强** = 拿到原文可回查；**中** = 只核到书目，原句来自他人引用；**通识** = 到处在说，追不到原始出处。
> 原始素材在 `_trash\组织协作调研-素材-20261114.md`，52 条以上 URL 在里面。

## 一句话

**人类的组织结构主要是为了「减少需要协调的量」，不是为了「提高协调的效率」。多智能体的实践多数在做后者，这是最大的方向性错误。**

## 一、先摆三个能回查原文的数字

### 1. 沟通路径 = n(n-1)/2

布鲁克斯《人月神话》1975 年第 2 章原文：

> *If each part of the task must be separately coordinated with each other part, the effort increases as n(n-1)/2. Three workers require three times as much pairwise intercommunication as two; four require six times as much as two.*

5 人 10 对，10 人 45 对，20 人 190 对。

**同一个公式康威 1968 年就给过一遍**，措辞不同：*the number of possible communication paths in an organization is approximately half the square of the number of people in the organization*。

**但要注意两件事**（原文里都写了，转述时常被删）：

- 它算的是**路径数，不是成本**。布鲁克斯的完整模型是「线性培训 + 二次沟通」两部分，不是单纯的 n²。
- 他自己说这是「极端简化」（oversimplifying outrageously），是修辞不是推导。

### 2. 跨地点协作 12.7 天，同地点 4.9 天

Herbsleb 与 Mockus，2003，IEEE Transactions on Software Engineering 29(6):481-494。数据来自朗讯科技真实变更记录：**同一个网络单元、同一种变更**，从第一个人动手到最后一个人完工的工作日数。

| 协作结构 | 工作日 |
|---|---|
| 单站点 | **4.9** |
| 多站点 | **12.7** |

这条比任何「沟通很重要」都好用，因为它是**同一种工作、同一套代码库、只差协作结构**的对照。

### 3. 被打断之后：更快，但更累

Gloria Mark 等人，CHI 2008，48 名被试，邮件分类任务。表 1 原始数字（分钟）：

| 条件 | 平均完成时间 |
|---|---|
| 不打断 | 22.77 |
| 同上下文打断 | 20.31 |
| 不同上下文打断 | 20.60 |

论文原话：被打断的人用更少时间完成任务，质量没有差别，但压力、挫败感、时间压力、努力感都显著更高。**人靠加快速度补偿打断，代价不在时间上。**

## 二、公司靠什么解决协调问题

六个机制，按「见效程度」排：

**1. 组织结构本身。** 这是最大的一条，也是最容易被忽略的。Conway 1968 的结论原句：*organizations which design systems are constrained to produce designs which are copies of the communication structures of these organizations*。

他还给了一句更狠的：*there is no such thing as a design group which is both organized and unbiased*。因为「组织团队」这个动作本身已经做了一批设计决定。

**2. 划自包含任务。** Galbraith 的组织信息处理理论：任务不确定性越大，执行过程中需要处理的信息越多。所以组织有两条出路：**降低信息处理需求**（留松弛资源、划自包含任务），或者**提高信息处理能力**（加信息系统、加横向关系）。

**3. 培训**。布鲁克斯原文里那一半常被漏掉：新增的沟通负担由两部分组成，培训和人沟通。每个新人都要被教会技术、目标、策略、计划，**这部分不可拆分，随人数线性增长**。

**4. 权威裁决。** 两个人意见不合，有 manager 拍板。这是人类组织最便宜、最常被用到的冲突解决机制。

**5. 隐性知识。** Polanyi：*we can know more than we can tell*。写不下来的东西（手感的判断、什么情况下该破例、这个客户为什么难缠）只能靠共事、示范、反复试错获得。管理学里 Nonaka 1994 把它变成了正经理论（Crossref 引用数 11,611），命题是「组织知识通过隐性与显性知识的持续对话被创造」。

**6. 小团队 + 单一负责人。** 「两个披萨团队」的机制解释是：人少时隐性知识靠日常接触就能同步，不需要写。亚马逊官方页给的机制是降低官僚、缓解「群体越大个人产出越低」（林格曼效应）。

但这里有个反直觉的事实：**亚马逊内部后来发现决定成败的不是小，而是那个「单一负责人」（single-threaded leader）**。原话：预测团队成功的最强因素不是它小不小，而是有没有一个具备技能、权限和经验的人来组建并管理它。而且「即使在亚马逊也出了名地难找」。

## 三、逐条对到 multiagent：哪些有对应物

这张表是全文最该看的部分。

| 人类的机制 | multiagent 里有没有 | 差在哪 |
|---|---|---|
| 组织结构减少沟通量 | **有，就是切包** | 但多数人切的是「任务」不是「写边界」，切完仍要互相看 |
| 划自包含任务 | **有，就是隔离上下文** | 隔离了就没人能追问，中途改不了方向 |
| 培训（线性成本） | **有，就是系统提示和 brief** | agent 每次从零开始，等于**每场都重新培训**，成本线性却按场次累计 |
| 权威裁决 | **没有** | 子代理冲突时，只有「更上层更强的模型」来收，它没有权威，只有概率更高的判断 |
| 隐性知识 | **没有对应物** | agent 的经验不会自己长，必须显式写下来（这就是 `prompt-inject.md` 和 `fact-wiki` 存在的理由） |
| 小团队 + 单一负责人 | **有，就是 lead + 少量子代理** | 但 lead 的「管理幅度」被 maxDepth=1 卡死，只能一层 |
| 共同背景（共享心智模型） | **没有** | 同一团队的两个人有大量不必重述的共识，两个子代理之间什么都没有 |

**这张表最右边那一列，就是多智能体为什么贵。**

Anthropic 的 15 倍 token 开销，逐项对就是这张表：每次派活都要「重新培训」（brief 里重述任务、约束、格式），每次交互都要走「显式沟通」（没有共享背景兜底），冲突没有裁决者只能靠汇总。

## 四、三个类比会失灵的地方

**失灵一：人开会是廉价广播，agent 共享上下文是平方成本。**

十个工程师开一次站会，成本是十个人的十分钟，信息同时到达所有人。十个子代理「共享上下文」，等于每个都要读另外九个的全部输出，token 按平方涨。

**人是低带宽但便宜的广播，agent 是高带宽但昂贵的点对点。**

**失灵二：人靠共享背景省掉大量沟通，agent 每次都从零。**

老员工不用被告知「我们这边测试跑失败先看日志」，因为他在这个环境里待过。新子代理不知道，你必须写进 brief。所以**人的组织可以用「默契」降低成本，agent 只能用「文档」**。

这解释了为什么 Anthropic 附录里那条「子代理把结果写到文件，只回传路径」这么重要：那是给 agent 造一种「可以回去查的背景」。

**失灵三：人有权威和激励，agent 没有。**

Cognition 那个 Flappy Bird 例子，最后一步「收拾两个误解」在人类组织里是组长干的，他有权限说「重做，按这个风格」。主 agent 没有这个权限，它只能再花一轮去调和。

而且人还有责任：做砸了要被追。agent 没有这个压力，它的「自信」和「正确」之间没有相关性。这正是为什么「不采信子代理自述」是硬规则。

## 五、Conway 定律在 agent 上的直接推论

**推论一：你的 agent 拓扑会印在产出上。**

Conway 的原文说，组织会「把自己盖在它做的每一个设计上」（stamp out an image of itself）。换成 agent：如果你按「前端 / 后端 / 数据库」切三个 agent，产出就会在接口处长出三套沟通约定，而不是一套统一设计。

Cognition 的 Flappy Bird 例子是这条的完美案例：两个子代理之间**没有沟通路径**，所以「视觉风格统一」这个设计决定根本没有人做。

**推论二（逆 Conway）：先定你想要的架构，再切 agent。**

ThoughtWorks 2014 年 7 月的雷达条目，原话：*The 'Inverse Conway Maneuver' recommends evolving your team and organizational structure to promote your desired architecture.*

对应到 agent：**先想清楚产出应该长什么样，再决定切几个子代理、怎么切。** 反过来（先按现成的人手切，再指望产出自然整齐）就是 Conway 说的「被迫产出」。

**推论三：委派那一刻就窄化了空间。**

Conway 原话：*Every time a delegation is made and somebody's scope of inquiry is narrowed, the class of design alternatives which can be effectively pursued is also narrowed.*

这条对 agent 的意义：**子代理的 brief 写得多具体，它就多想不出别的方案。** 写太窄，它交回一个符合要求但整体不协调的结果；写太宽，它跑偏。这就是为什么「意图工程」在多智能体里是瓶颈，不是可选项。

## 六、两个流行说法是假的（顺便学证据分级）

**①「被打断后要 23 分钟才能恢复专注」。** 这个数字被广泛挂在 Gloria Mark 的 CHI 2008 论文上。**那篇 PDF 全文检索里没有这个数字**，论文结论几乎相反（被打断的人干得更快）。新西兰怀疑论者协会 2023 年做过同样核查，结论一致，并指出这个数字是别人读了论文之后编出来的。

**②「领导层的信息只有 20%~25% 被下级正确理解」。** 中文管理期刊 2011 到 2020 年至少五篇在转抄，都归到「美国加利福尼亚州立大学的研究」。**没有一条给出作者、年份、期刊、样本。**

**要讲层级沟通失真，用这个更站得住**：O'Reilly 1978（Human Relations 31(2):173-193）的实验结论是：存在一种偏向，会把某类信息从向上传递中筛掉；对收信人信任度低时，发信人显著更多地压下信息，尤其是对自己不利的信息；信息失真程度与工作满意度、个人与团队绩效显著负相关。

**这条方法的用法比结论更有价值**：一个说法流传越广、越好记、越像常识，越该去追原始出处。追不到就标「流传甚广但查不到原始研究」，不要写成「研究表明」。

## 七、对老大的意义

**1. 你已经在做「培训」这一半，但没意识到它是最贵的线性成本。**
`prompt-inject.md` 26K 字符 + 工作区 `AGENTS.md` 17.8K + home 级 2.5K，这三块就是「每场重新培训」。布鲁克斯说培训成本随人数线性增长；换成 agent，它随**每次派活的子代理数**线性增长，且按场次累计。

**推论**：减少子代理数量省的钱，可能比优化任何提示词都多。

**2. 你的记忆系统，实际在替 agent 补「隐性知识」。**
人类靠共事获得隐性知识，agent 没有这个通道。你的 `fact-wiki`（踩过的坑 + 可重放命令）、`digests`（你说过的判断）、`active-prefs`，本质是把「本该长在身上的东西」写成了可传递的形式。

这条给你一个判据：**写记忆的时候问「这是不是一条原本靠共事才能学到的东西」。** 是，就值得写；不是，可能只是任务状态。

**3. 你要的「Leader 只做判断」，在人类组织里有对应物，但缺两样。**
对应物是亚马逊的 single-threaded leader：一个具备技能、权限和经验的人，管一件只专注这件事的事。缺的两样是**权威**和**责任**。这两样补不上，Leader 就只能靠「抽查验收」来替代权威，这也是为什么那一环不能省。

**4. 最该抄的一条：Galbraith 的二分。**

组织要么**降低信息处理需求**，要么**提高信息处理能力**。多数人本能地做后者（加信道、加消息、加会），而成功组织多数做前者（划自包含任务）。

换到 agent：**优先切包，不优先加协调层**。你上一个问题里想加的协调者，属于后者。

## 九、术语速查

| 词 | 一句话 |
|---|---|
| 同态（homomorphism） | 两个结构保持形状对应。Conway 用它说组织和系统的关系 |
| 逆 Conway 操作 | 先改组织结构，去逼出你想要的系统架构 |
| 自包含任务 | 一个不用跟别人来回协调就能做完的任务单元 |
| 隐性知识 | 知道但说不出来的部分，只能靠共事传递 |
| 林格曼效应 | 群体越大，人均出力越低 |
| 单一负责人（STL） | 一个对某件事负全责的人，亚马逊发现它比团队小更决定成败 |
| 沟通带宽 | 一次沟通能传多少信息。共享上下文带宽高，传结果带宽低 |
