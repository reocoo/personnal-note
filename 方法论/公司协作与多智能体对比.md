# 公司里人怎么协作，以及它跟多智能体哪里像、哪里不像

> 这篇写给刚接触 agent 的人。先把要用的词解释完，再讲对比。
> 材料来自八项经典理论与实证研究，每项都标了证据档次：**强** = 拿到原文可回查；**中** = 只核到书目，原句来自别人引用；**通识** = 到处在说，追不到原始出处。
> 原始素材在 `_trash\组织协作调研-素材-20261114.md`。

## 零、先把要用的五个词说清

不解释这五个词，后面的对比就是天书。

**① agent（智能体）**：一个能自己调工具、看结果、再决定下一步的 AI 程序。它跟「聊天机器人」的区别是：聊天机器人只能说，agent 能动手（读文件、跑命令、查网页）。

**② 多智能体（multi-agent）**：把一件事拆给好几个 agent 干。注意「好几个」不是指开了几个聊天窗口，是指它们之间有分工、有交付关系。

**③ 子代理（subagent）**：被派活的那个 agent。它有自己的上下文窗口（下面解释），干完把结果交回来。

**④ 上下文窗口（context window）**：一个 agent 一次能「看见」的全部文字量，单位是 token。装不下的部分它看不见，你要么压缩，要么让它去查。

**⑤ token**：模型计量的最小单位。英文大约 4 个字符算 1 个 token，中文大约 1 个字算 1 到 2 个 token。**说「成本」的时候基本都在说 token**，因为 API 按 token 收费，速度也按 token 算。

再补两个我后面要用的行话：

**⑥ 切包**：把一个大任务拆成几份互不重叠的活。**关键是「互不重叠」**：如果两份活都要改同一个文件，那就不叫切开了。

**⑦ 拓扑**：谁跟谁连着。三个 agent 串成一条线是一种拓扑，三个都连到主会话是另一种。

## 一、核心判断，先说结论

**人类的组织结构，主要目的是「减少需要协调的量」，不是为了「让协调本身更快」。**

这句话是整个对比的支点。展开说：

假设一件事要五个人做。如果五个人都要随时对进度、随时确认对方在干什么，那光是沟通就能把活拖死。所以公司会做一件事：**把这五个人分开，各自管一块，事先说好接口，平时不用互相汇报**。

公司里那些看起来「官僚」的东西（部门划分、职责边界、审批流程），多数是在干这件事：**减少必须发生的沟通次数**，而不是让每次沟通变快。

而多智能体的实践，多数是在提升协调效率（加消息、加中间层、加汇总），很少去减少协调量。**方向反了。**

出处是 Galbraith 的组织信息处理理论：任务不确定性越大，执行过程中需要在决策者之间处理的信息越多。组织只有两条出路：**降低信息需求**（划自包含任务、留缓冲），或者**提高处理能力**（加信息系统、加横向沟通）。成功的组织多数做前者。

## 二、三个能回查原文的数字

这三个数字我都能指到原文，用的时候可以直接引。

### 数字一：n(n-1)/2 条沟通路径

**先解释这个式子**：n 是人数。n 个人两两配对，配对数 = n×(n-1)÷2。四个人是 4×3÷2 = 6 对，十个人是 45 对，二十个人是 190 对。

**它测的是「可能的沟通路径数」，不是「沟通成本」。** 这个区别很重要，后面会讲。

布鲁克斯《人月神话》1975 年第 2 章原文：

> *If each part of the task must be separately coordinated with each other part, the effort increases as n(n-1)/2. Three workers require three times as much pairwise intercommunication as two; four require six times as much as two.*

翻译：如果任务的每一部分都必须跟其他每一部分单独协调，开销按 n(n-1)/2 增长。三个人需要的两两沟通是两个人的三倍，四个人是六倍。

**同一个式子，康威 1968 年就写过一遍**，措辞不同：一个组织里可能的沟通路径数，大约是人数平方的一半。

**但原文里有两句常被漏掉的话**：

1. 布鲁克斯的完整模型是「**线性培训 + 二次沟通**」两部分，不是单纯的 n²。培训那一半是：每个新人都要被教会技术、目标、总体策略、工作计划，**这部分拆不开，随人数线性涨**。
2. 他自己说这是「极端简化」（oversimplifying outrageously），是打比方，不是推导出来的公式。别拿它当精算工具。

**为什么这条对 agent 直接成立**：派一个子代理，你要在 brief 里把任务、约束、输出格式重述一遍。这就是「培训」，而且**每个子代理都要重述一次，每场任务都从零开始**。人培训一次能管几年，agent 每个任务都要重新培训。

### 数字二：跨站点 12.7 天，同站点 4.9 天

出处：Herbsleb 与 Mockus，2003，IEEE Transactions on Software Engineering 29(6):481-494。数据来自朗讯科技的真实变更记录。

**测的是什么**：同一个网络单元的一次变更，从第一个人动手到最后一个人完工，花了多少个工作日。

| 协作结构 | 工作日 |
|---|---|
| 所有人同一地点 | **4.9** |
| 分散在多个地点 | **12.7** |

**为什么这条硬**：同一种工作、同一套代码、只差「人是不是坐在一块」。这是天然的对照实验，比任何「沟通很重要」的空话都有说服力。

**为什么它对 agent 有意义**：多站点的人只能靠邮件和会议同步，带宽低。子代理之间只能靠回传的报告同步，带宽也低。反过来，坐在一个会议室里的人带宽高（能看对方屏幕），这对应 agent 的「共享上下文窗口」。

**Anthropic 的 15 倍 token 开销，本质就是「跨站点协作」的价钱。**

### 数字三：被打断之后 22.77 分钟 vs 20.31 分钟

出处：Gloria Mark 等，CHI 2008（人机交互顶会），48 名被试，任务是整理邮件。

| 条件 | 平均完成时间 |
|---|---|
| 不打断 | 22.77 分钟 |
| 同上下文打断 | 20.31 分钟 |
| 不同上下文打断 | 20.60 分钟 |

**结论反直觉**：被打断的人反而更快做完，质量没差别，但压力、挫败感、时间压力、努力感显著更高。人靠加快速度来补偿打断，**代价不在时间上，在人身上**。

**为什么它对 agent 有意义**：如果你经常打断一个长任务去插一句「顺便把 X 也做了」，时间上看起来没损失，但如果那是人，代价是累。agent 没有「累」，但它有对应的东西：上下文被塞进无关任务，可能挤掉原本要用的材料。

## 三、公司靠什么解决协调问题：六个机制

**1. 组织结构本身。**

这是最大的一条，也是最难看见的。康威 1968 年的结论原话：

> *organizations which design systems are constrained to produce designs which are copies of the communication structures of these organizations*

翻译：设计系统的组织，被迫做出跟自己的沟通结构同构的设计。

**举个例子**：一家公司分前端组、后端组、数据库组，各自开会、各自汇报。他们做出来的系统，接口处就会有三套约定，而不是一套统一的。**因为「前端和后端怎么对齐」这件事，在他们的组织里有沟通路径；「前端和数据库怎么对齐」没有。**

他还写了一句更狠的：不存在既被组织起来、又没有偏向的设计团队。因为「组织团队」这个动作本身已经做了一批设计决定（谁跟谁一组、谁向谁汇报）。

**2. 划自包含任务。**

Galbraith 说的「降低信息需求」的具体做法：让一个人或一个小组负责一件从头到尾的事，不用跟别人来回确认。

**例子**：让一个人负责「用户注册功能」的全部（前端页面、后端接口、数据库表），他会自己处理内部的协调，对外只报一次「做完了」。

**3. 培训。**

布鲁克斯那「线性」的一半。新人进来要先被教会技术、目标、策略、计划，这段时间他产不出东西。人越多，这段总成本越高，而且**没法并行压缩**（你不能把「教会一个人」这件事拆给三个人分摊）。

**4. 权威裁决。**

两个人意见不合，有经理拍板。这是人类组织最便宜、最常用的冲突解决机制。**不需要说服对方，只需要有人能下决定。**

**5. 隐性知识。**

Polanyi 的说法：*we can know more than we can tell*（我们能知道的比能说出来的多）。

具体指什么？一个老员工知道「这个客户脾气急，方案要先给结论」「测试挂了先看日志最后三行别看全部」「这个模块的历史包袱在哪」。**这些他都写不进交接文档**，因为写的时候想不全，而且他觉得理所当然。

管理学里 Nonaka 1994 把这变成了正经理论：组织知识靠隐性知识和显性知识的持续对话来创造。这篇被引了 11,611 次（Crossref 计）。

**为什么这条对 agent 特别重要**：agent 完全没有隐性知识。它每次都是新员工，而且不会在共事中积累「手感」。所以那部分东西**必须被显式写下来**，否则永远不存在。

**6. 小团队 + 单一负责人。**

「两个披萨团队」的说法归到贝索斯：一个团队大到两个披萨喂饱就够了。但流传的「6 到 10 人」是后来的转述，**亚马逊官方页面里没写人数**。

官方页给的是机制：小团队把官僚降到最低、把专注做事的时间提到最高，还能缓解「群体越大个人产出越低」（这叫林格曼效应，1913 年拉绳实验的发现）。

**但这里有个反直觉的事实**：亚马逊后来发现，决定团队成败的不是小，而是有没有一个「单一负责人」（single-threaded leader）：一个具备技能、权限和经验的人，管一件只专注这件事的事。而且这种人在亚马逊内部也「出了名地难找」。

## 四、七个机制对照到 agent：哪些有，哪些没有

这张表是全文最该看的部分。左边是人类组织里真实存在的东西，右边是 agent 里有没有对应的。

| 人类的机制 | agent 里有吗 | 差在哪（白话） |
|---|---|---|
| 组织结构减少沟通量 | 有，就是切包 | 但多数人切的是「活」不是「写边界」，切完两份活还要改同一个文件，等于没切 |
| 划自包含任务 | 有，就是给子代理独立上下文窗口 | 隔离了就没人能中途追问，方向错了只能等它交回来再返工 |
| 培训（线性成本） | 有，就是系统提示和任务 brief | 人培训一次管几年，agent 每个任务都从零被培训一次，且每个子代理各培训一次 |
| 权威裁决 | **没有** | 两个子代理结论冲突，没有谁有权拍板。只能让更上层、更强的模型去调和，那是概率更高的判断，不是权威 |
| 隐性知识 | **没有** | agent 不会在共事中长出手感。经验必须被写成文件，否则下一次它还是不知道 |
| 小团队 + 单一负责人 | 有，就是主会话带少量子代理 | 但主会话能带几个被硬限制（本机 `maxDepth=1`，只能带一层），管不了两层 |
| 共同背景（默契） | **没有** | 同一个团队的人有大量不必重述的共识（「我们这边挂了先看日志」），两个子代理之间完全是空白 |

**右边那一列就是多智能体为什么贵。**

Anthropic 实测多智能体比普通聊天多用 15 倍 token。逐项对就是这张表：每次派活重新培训一次（brief 里重述所有约束），每次交互都要显式沟通（没有默契兜底），冲突没有裁决者只能靠汇总。

## 五、三个类比会失灵的地方

类比能帮你理解，但要知道它在哪断掉。

### 失灵一：人开会是廉价的广播，agent 共享上下文是平方的账单

十个工程师开站会，成本是十个人各十分钟，信息同时到达所有人。这是**广播**：一次发送，多个接收，单价不变。

十个 agent「共享上下文」，等于每个 agent 都要读另外九个的全部输出。token 按对数涨，不是按人数涨。

**一句话**：人是低带宽但便宜的广播，agent 是高带宽但昂贵的点对点。

### 失灵二：人靠共享背景省掉大量沟通，agent 每次从零

老员工不用被告知「我们这边测试跑失败先看日志最后三行」，因为他在这个环境里待过，知道。

新子代理不知道，你必须写进 brief。**人的组织可以用默契降低成本，agent 只能用文档。**

这也解释了为什么 Anthropic 要在附录里专门写一条：让子代理把结果写到文件，回传给主会话的只是一条路径。**那是在给 agent 造一种「可以回去查的背景」**，因为共享上下文太贵，存到外面再按需读更便宜。

### 失灵三：人有权威和激励，agent 都没有

回到「做一个 Flappy Bird 克隆」那个例子：子代理 A 做成超级马里奥风格的背景，子代理 B 做的鸟不像游戏素材。

人类组织里，这时候组长会说「重做，按这个风格」，因为他有权。主会话没有这个权，它只能再花一轮去调和两份不协调的产出，然后自己判断该改哪边。

另外人还有责任：做砸了要被追。agent 没有这个压力，所以它的「自信」和「正确」之间没有相关性。

**这正是为什么「不采信子代理的自述」必须是硬规则。** 它说「已验证」，你要自己去跑一遍。

## 六、康威定律在 agent 上的三个用法

### 用法一：你的 agent 拓扑会印在产出上

康威说组织会「把自己盖在它做的每一个设计上」。

换成 agent：如果你按「前端 / 后端 / 数据库」切三个子代理，产出就会在接口处长出三套沟通约定，而不是一套统一设计。**因为「风格统一」这个决定，没有落在任何一个 agent 的职责里。**

### 用法二（逆康威）：先定你想要的产出长什么样，再切 agent

ThoughtWorks 2014 年 7 月的技术雷达条目原话：

> *The 'Inverse Conway Maneuver' recommends evolving your team and organizational structure to promote your desired architecture.*

翻译：逆康威操作主张反过来，先演化团队与组织结构，去逼出你想要的架构。

对应到 agent：**先想清楚产出应该长什么样（一份统一的、还是三份各管一段的），再决定切几个子代理、怎么切。** 反过来（先按现成人手切，再指望产出自然整齐）就是康威说的「被迫产出」。

### 用法三：委派那一刻就窄化了可能

康威原话：

> *Every time a delegation is made and somebody's scope of inquiry is narrowed, the class of design alternatives which can be effectively pursued is also narrowed.*

翻译：每次委派都会窄化某个人的探索范围，于是能被有效探索的设计方案类别也变窄了。

**具体到 agent**：子代理的 brief 写得越具体，它就越想不出别的方案。

- 写太窄：「把这个函数的参数从 int 改成 string」→ 它只改这一处，不动上游
- 写太宽：「优化这个模块」→ 它跑偏
- 合适：给目标 + 边界 + 验收标准，不给实现路径

这也是为什么「意图工程」在多智能体里是瓶颈而不是可选项。

## 七、两个流行说法是假的

这一段的价值不只在纠正数字，更在教你一个判断方法。

### 假说法一：「被打断后要 23 分钟才能恢复专注」

这个数字被广泛挂在 Gloria Mark 的 CHI 2008 论文上。**那篇论文 PDF 全文检索里没有这个数字**，而且结论几乎相反（被打断的人干得更快）。

新西兰怀疑论者协会 2023 年做过同样的核查，结论一致，并指出这个数字是别人读了论文之后编出来的。

### 假说法二：「领导层的信息只有 20%~25% 被下级正确理解」

中文管理期刊 2011 到 2020 年至少五篇在转抄，都归到「美国加利福尼亚州立大学的研究」。**二十年里没有一条给出作者、年份、期刊、样本。**

### 那该用什么

讲层级沟通失真，用这个：O'Reilly 1978（Human Relations 31(2):173-193）的实验结论。

三项发现：存在一种偏向，会把某类信息从向上传递中筛掉；对收信人信任度低时，发信人显著更多地压下信息，**尤其是对自己不利的信息**；信息失真程度与工作满意度、个人和团队绩效显著负相关。

**方法的用法比结论更值钱**：一个说法流传越广、越好记、越像常识，越该去追原始出处。追不到就写「流传甚广但查不到原始研究」，别写成「研究表明」。

## 八、对老大的具体意义

**1. 你已经在做「培训」那一半，但没意识到它是最贵的线性成本。**

`prompt-inject.md` 26K 字符、工作区 `AGENTS.md` 17.8K、home 级 2.5K，这三块就是每场重新培训一次。布鲁克斯说培训成本随人数线性增长；换成 agent，它随「每次派几个子代理」再乘一遍。

**推论**：少派一个子代理省下的钱，可能比优化任何一段提示词都多。

**2. 你的记忆系统，实际在替 agent 补隐性知识。**

人类靠共事获得隐性知识，agent 没有这个通道。你的 `fact-wiki`（踩过的坑 + 可重放命令）、`digests`（你说过的判断）、`active-prefs`，本质是把「本该长在身上的东西」写成可以传递的形式。

**判据**：写记忆的时候问一句「这是不是一条本来靠共事才能学到的东西」。是，就值得写；不是，可能只是任务状态。

**3. 你要的「Leader 只做判断」，在人类组织里有对应物，但缺两样。**

对应物是亚马逊的 single-threaded leader：一个有技能、有权限、有经验的人，管一件只专注的事。缺的两样是**权威**和**责任**。

这两样补不上，Leader 就只能靠「抽查验收」来替代权威。这也是为什么那一环不能省。

**4. 最该抄的一条：优先切包，不优先加协调层。**

Galbraith 的二分里，加协调层属于「提高处理能力」，划自包含任务属于「降低信息需求」。**成功组织多数做后者。**

## 十、术语速查

| 词 | 一句话 |
|---|---|
| agent | 能自己调工具、看结果、决定下一步的 AI 程序 |
| 子代理 | 被派活的 agent，有自己的上下文窗口，干完交回结果 |
| 上下文窗口 | 一个 agent 一次能看见的全部文字量，单位 token |
| token | 模型的计量单位，英文约 4 字符，中文约 1 到 2 个字 |
| 切包 | 把大任务拆成几份互不重叠的活 |
| 拓扑 | 谁跟谁连着，串成一条线还是都连到中心 |
| 同态（homomorphism） | 两个结构保持形状对应。康威用这个词说组织与系统的关系 |
| 逆康威操作 | 先改组织结构，去逼出你想要的系统架构 |
| 自包含任务 | 一个不用跟别人来回协调就能做完的任务单元 |
| 隐性知识 | 知道但说不出来、只能靠共事传递的部分 |
| 林格曼效应 | 群体越大，人均出力越低 |
| 单一负责人 | 一个对某件事负全责的人，亚马逊发现它比团队小更决定成败 |
| 沟通带宽 | 一次沟通能传多少信息。共享上下文带宽高，只传结果带宽低 |
