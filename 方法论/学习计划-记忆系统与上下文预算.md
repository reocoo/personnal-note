# 学习计划 · 记忆系统与上下文预算（2026-11-07 起）

> 来源：83 号项目 `83-DSH记忆系统优化\`。那一轮干了三件事：实测本机每轮注入了多少、质疑一份改造计划、跟那份计划的作者打了一场辩论。
> **这一份不是项目记录，是把那三件事里能迁移到别的任务上的东西提出来，排成能练的次序。**

---

## 一、这一轮到底学了什么

一句话：**上下文是有限预算，不是自由资源。** 谁能说清「每轮固定花掉多少、花在哪、哪些是白花的」，谁就能把 agent 调好。

具体分成四块能力，块与块之间有依赖，不能跳。

| 块 | 能力 | 现在状态 |
|---|---|---|
| A | 量出真实的注入账（不靠感觉） | 我做出来了，方法可复用 |
| B | 判断哪些内容该常驻、哪些该按需 | 有判据，但判据来自别人，我没独立验证过 |
| C | 质疑一份方案（分清「数错了」和「读法错了」） | 做了，且**自己错了两条** |
| D | 把上面的东西落成可回滚的改造 | 计划写了，**一步没执行** |

**D 是零。** 计划再漂亮也是纸。这一轮的真实进度是 A 完成、C 完成一半、B 只有别人的判据、D 没动。

## 二、四个块各自的「会」与「不会」怎么判

按 65 号 `掌握度摸查规程.md` 的五状态走，不跳级。默认全部 `未探测`。

### A · 量注入账

**要会到什么程度**：拿一份 `.zstd` 会话日志，能自己写出脚本，量出每一段注入的真实字节，且**说得清每段属于哪一类**（人格 / 项目约定 / skill 索引 / 运行环境）。

**已验证会**（有正面证据）：
- 会解多帧 zstd（`zstandard.stream_reader`，不是 `decompress`）
- 会按 `type` 字段分出 `system/message` / `user/message` / `request/header`
- 会用 `content[0].text` 取正文

**踩过的坑，必须记住**：
- 递归抓所有 `text` 键会重复计数（`source.sections[]` 里有同名字段）。**这条让我把 830 错判成 1,570，把正确的数字说成错的。**
- `request/header` 的工具定义在 `data.header.tools`，不是 `data.tools`。

**未探测**：真实 token 数（有 `input_tokens` 字段但没取过）。

### B · 判「该常驻还是该按需」

**现在只有别人的判据**，来自 81 号会议：

> 只有稳定不变、一直需要注入的东西，才值得做成 memory 或写进 `AGENTS.md`。

**我没独立验证过这条。** 什么算「稳定不变」？登记表加了 92 行算不算稳定？这些是空白。

这是 B 块最大的缺口，也是**下一轮最该练的**。

### C · 质疑方案

**做对的部分**：先复算主账、再逐条对原文、每条质疑带原始字节、明确标证据边界。

**做错的部分，比做对的更值得记**：

1. **只抽了「值」没抽「提取器」。** 我拿自己的脚本输出当事实，没验脚本本身。对手一句「你自己量一次」就翻掉了。
2. **把「设计行为」判成「缺陷」。** 4 个 skill 不进索引是 `disable-model-invocation: true` 主动关的，我判成「门禁抓不到的坏样本」，还据此推「P2 设计有洞」。
3. **拿原文数字当 catalog 数字。** sw-dialogue 1,026 B 是 SKILL.md 原文，catalog 里已被截到 500 字符。

**共同点**：三次都是**没看第二层**。看到数字没看它怎么来的，看到现象没看它为什么这样。

### D · 落地改造

**零。** 一步没动。这决定了我对 P0~P5 的所有判断都是**纸面推演**，没有一次真实执行的反馈。

## 三、练习次序（按依赖排，不按重要性排）

### 第 1 练 · 重做一次注入账，不许看我的脚本

**做什么**：自己从 `~\.dsh\sessions` 挑一个会话，解压，量出五段字节，跟 171,867 对。

**判据（三条全过才算「已验证会」）**：
1. 五个数全部对上（65,536 / 63,187 / 42,052 / 830 / 262）
2. 能说出**为什么** `runtime` 那段的 830 是字节不是字符（提示：看 `content` 长度和 `chars` 差多少）
3. 能指出递归抓 `text` 键会多算多少

**为什么排第一**：这是所有后续判断的地基。地基错了，后面全错，而且错得很像对的。**这一条我自己就栽了。**

### 第 2 练 · 自己给「该常驻」定判据

**做什么**：拿 `AGENTS.md` 现在的 11 个段落，逐段判「每轮必读 / 按需读」，并**写出你的判据**。

**不许用会议的判据**，因为那条太抽象，判不出登记表算哪类。你要给出能当场用的判据，比如「这段内容变了，我的行为要不要跟着变？变了的话是这一轮就要变，还是下次碰到相关任务才变？」

**判据（两条）**：
1. 11 段全部有归类，每段附一句理由
2. 判据本身能**反过来用**：拿一段没见过的内容，你的判据能给出答案，不用再讨论

**为什么排第二**：这是 P0 的真正依据。老大现在只等你回答一个问题：登记表要不要每轮进来。**你自己给不出判据，就回答不了这个问题。**

### 第 3 练 · 执行 P0，然后验它

**做什么**：真搬。搬到 `REGISTRY.md`，改 `AGENTS.md`，新开探针会话读日志。

**判据（四条，缺一不算会）**：
1. `AGENTS.md` ≤ 30,000 B
2. `REGISTRY.md` 表格行数 = 92
3. 探针会话日志里 **`truncated` 和 `omitted` 都不出现**
4. 故意把 `REGISTRY.md` 删掉，看会发生什么 —— **这一步最重要**，它测的是「我到底会不会主动去读那个文件」

**为什么排第三**：前两练都是纸上的，这一练是第一次真实执行。而且第 4 条判据会暴露一个真问题：`REGISTRY.md` 不注入了，**我怎么知道要去读它**。

### 第 4 练 · 做一次有对手的质疑

**做什么**：以后任何一份别人（或我自己）写的方案，**先自己写质疑，再开一个对手辩护**。

**从这一轮学到的操作**：
- 对手必须是**独立上下文**，读同一批文件，明确授权「全力辩护」
- 开场不让它看我的质疑清单（否则它顺着我的框架辩护）
- 它的反驳必须落到可复算的东西上
- **我必须先验自己的提取器，再拿提取器的输出质疑别人**

**判据**：
1. 对手至少推翻我一条（推不翻说明我找的对手太弱，或者我的质疑太软）
2. 我自己至少能指出对手一条错的
3. 双方都能说出「这条维持未探测」

**为什么排第四**：这一练的成本最高（这一轮烧了半小时、对手中途失败），但收益也最高。**我这轮 12 条质疑里错了 2 条，全靠对手翻出来的。** 没有对手，这两条会一直留在报告里。

## 四、这一轮暴露的三个长期毛病

不是这一轮特有的，是会复发的。

### 毛病 1 · 只看一层

三次错都是同一个形状：看到数字没看它怎么来的，看到现象没看它为什么。**修法不是「更仔细」，是「每次拿数字前先问：这个数是哪个程序算出来的，那个程序本身对不对」**。

### 毛病 2 · 把设计当成缺陷

看到「不符合我的预期」就判成「有问题」，没先问「这是不是有人故意这么设的」。`disable-model-invocation` 那次就是这样。

**修法**：判缺陷之前，先找「有没有一个开关能让它变成这样」。

### 毛病 3 · 计划做得比自己执行得好

83 号的计划有六个阶段、每段带判据和回滚，写得很完整。**但我做的 v2 计划一样一步没执行。**

**修法**：计划里的第一个阶段必须是**一次调用就能做完的事**。不是「P0 六个动作」，是「新建 REGISTRY.md 并粘贴 92 行」这**一个动作**。
