# Anthropic 工程心法（四篇合卡）

> 一句话：这是**操作卡**，不是读书笔记。任务开工前过一遍下面八步，每一步都给了判据和一句能直接说出口的话。
> 什么时候读：接手任何一件「做完了要交出去」的活之前。纯聊天、纯查事实不用。

四篇原文的详细笔记在目录里另存（`Felix-野心四维度.md` 等），**这张卡是它们的压缩版**，日常只读这张就够。

## 为什么这四篇能合成一张

三个作者，四篇文章，跨越 2026 年 1 月到 10 月，却撞在同一条上：

> **别让模型自己给自己打分。**

| 谁 | 在哪一篇 | 怎么说的 |
|---|---|---|
| Felix Rieseberg | 《How to be more ambitious》 | Do not ask the model to judge itself（别让模型评判自己） |
| Thariq Shihipar | 《A Field Guide to Fable》 | 实现完之后让模型**反过来考你**，答错指回你跳过的章节 |
| Boris Cherny | Claude Code 创作人 13 条 | 给模型一个**验证自己工作的反馈回路**，成品质量 2~3 倍 |

三个人在不同时间、不同岗位独立得出同一条，这条的可信度比其他任何一条都高。**如果只记一件事，记这件。**

## 八步开工流程

### 第 1 步 · 先问这活值不值得做

**判据**：你是在消化别人给你的待办清单（backlog），还是在碰真正产生价值的部分？

Felix 第二篇的原话：工程师是被雇来产生业务价值的，不是来写程序的（Patrick McKenzie, 2011）。做法是把自己挂到公司赚钱的那部分上。

**这里的「业务价值」对学生怎么换算**：老师说要做的东西是 backlog，考试要考、你要靠它吃饭的能力才是价值。两者重叠时最省力，不重叠时至少要知道自己在做哪一边。

**一句能说的话**：「这件事做完，谁的日子会变好？如果没人，能不能换个做法。」

### 第 2 步 · 把「你不知道自己没说什么」挖出来

**判据**：你敢不敢说「我把要求写全了」？不敢就做这一步。

Thariq 给了个四分法，把「不知道」拆成四种：

| 类型        | 是什么               | 例子                       |
| --------- | ----------------- | ------------------------ |
| **已知的已知** | 已经写进提示词的要求        | 「用 C 写，不许用第三方库」          |
| **已知的未知** | 你知道自己还没想清         | 「内存要不要手动释放，我还没定」         |
| **未知的已知** | 你觉得太显然、根本不会写下来的偏好 | 「报错信息我想看到原文，别看不懂就自己总结」   |
| **未知的未知** | 压根没进过你脑子的角度       | 「这个程序在同学那台没装运行库的电脑上能不能跑」 |

**第四格最贵，也最难自己想到。** Thariq 的解法是让模型先做一次「盲区扫描」（blind spot pass）：让它读相关代码或材料，报出它会踩的坑，而不是直接开工。

**一句能说的话**：「先别写。读一遍这些材料，告诉我：一个老手在这里会做什么而我没要求？我会踩什么坑？」

### 第 3 步 · 抬到结果层，别停在任务层

**判据**：这件事做完以后**要开会讨论吗**？要，就值得再往上升一层。

Felix 的例子：一开始他让 Claude 修一个个具体的崩溃，后来直接要求「让我们的应用永远不崩溃」。前面那句锁死了你对问题范围的理解，后面那句没有。

**但有个前置条件，漏了这条就是空话**：抬高度要求你先改工作流。他要做到「应用不崩溃」，先做了三件事：崩溃报告能轻松拿到、每个版本对应到具体 git commit、给模型三台能自己复现问题的机器。**不做这些，「让应用不崩溃」只是一句好听的话。**

**一句能说的话**：「我想要的结果是 X（不是做 Y 这个动作）。为了让你能自己判断做到没有，你需要我提供什么？」

### 第 4 步 · 给它真器械，别让它假装专业

**判据**：它是真的换了工具，还是只换了词汇？

Felix 那句是全篇最扎人的：模型被要求「像专家一样」时，**通常只换词汇不换方法**。判断方法是看它伸手拿什么。它去画 Markdown 表格，你就坚持让它用数据库和统计模型。

Boris 的对应做法更硬：**接 MCP 给它真工具**（Slack、BigQuery、Sentry 那一类），而不是让它凭记忆描述。

**一句能说的话**：「别用 Markdown 表格糊弄我。用真正的做法，先说这个领域的顶级从业者会用什么工具，然后就用那个工具。」

### 第 5 步 · 目标可以不合理，但停止条件必须先定

**判据**：这件事有没有明确的「试几次就停」？

Felix 的原话是：网站要从 10 秒降到 5 秒？直接要 200 毫秒。模型说做不到，就再强调一遍这问题可以解，继续试。

**这条是我加的限制，原文没有，因为本机烧过钱**（63 号千问撞过风控、21 号 protocom 欠过费）。照原文裸用，「继续试」会从有野心变成没效率。

**一句能说的话**：「目标定 200 毫秒。但试满 5 轮就停，停下来的时候交一份清单：你试过哪些方案、每个卡在哪一步、下一步需要我先做什么。」

### 第 6 步 · 换语言：把名词换成动词

**判据**：你说的是「一个 PPT」「一份方案」这种名词吗？

Felix 引的是《The Art of Innovation》里的老招。季度评审不是「一个 PPT」，是「30 分钟内让一群很忙的人相信一个关于因果的故事，并在信息不全时做出决定」。

换成动词之后，**难点会自己冒出来**，而且你和模型都能看出该找哪个领域帮忙。

**一句能说的话**：「我要的不是一份文档，是让 X 在 Y 条件下做到 Z。按这个说，你会怎么拆。」

### 第 7 步 · 让它自己验，别让它自己判

**判据**：它交付的时候，**拿什么证明自己做对了**？

这一步是四篇的交叉点，回到开头那条。要分清两件容易混的事：

- **自评**（它说「我觉得没问题」）= 几乎零价值
- **自验**（它有办法跑一下、测一下、对一下）= 最高价值

Boris 给的数字最具体：有反馈回路时成品质量 **2~3 倍**，而且他把这条列为自己 13 条里杠杆最高的一条。他说的反馈回路是具体东西：跑测试、跑类型检查、跑 lint。

**本机的对应物**：`pwsh` 跑一遍、`wiki_index.py` 的 exit code、图片的 `naturalWidth`、网页的横向溢出读数。**能读出数字的都算，只在嘴上说「应该行」的不算。**

**一句能说的话**：「先告诉我你打算用什么证明它对了。这个证明必须是我能不靠你、自己重跑一遍的。」

### 第 8 步 · 交付后考自己一次

**判据**：能不能不看着成品，把它讲清楚？

Thariq 的做法是让模型**反过来出题考人**，答错的地方指回你跳过的那一段。他在演讲里讲了个更狠的观察：代码写完了不等于你懂了，而 PR 是要你去讲、去合并的。

**这条对老大最用得上的形态**：让模型出一份小测。答不出来，说明这一步你只是「拿到了结果」，没「获得能力」。

**一句能说的话**：「活儿干完了。出 5 道题考我，专挑我可能没细看的地方。我答错的，指回具体哪一段。」

## 两条容易被当成口头禅的补充

### 「更快」是最低一档，别把它当目标

Felix 把野心分四类（速度、高度、深度、广度），**明确跳过了速度**。理由很直白：那条路已经成熟，不需要创意。

用 AI 只图快，等于只用了它最便宜的那一档。

### 更容易构建 ≠ 产生价值

Thariq 在演讲收尾专门划了这条线。他自己也承认，用新工具把原来要几周的东西几小时做完时，他心里有失落感（写代码这件事本身在变）。

但更要紧的是下一句：**做得快不等于做得对**。有价值的结果仍然要反复试。

## 哪里会翻车

> 这一节是我的判断，不在原文里。

**1. 第 3 步（抬高度）和「任务没说清」长得几乎一样。** 我自己的判据是「抬完之后它还交得出可验证的产物吗」，但这个判据我没验证过。**如果你发现抬完以后模型开始写长篇计划、不产出东西，那就是抬过头了**，退回第 3 步上一档。

**2. 第 4 步有一段原文自己打架。** Felix 前半句说「模型被要求像专家时只换词汇不换方法」，后半句又说「你不必知道专家用什么，Claude 通常知道」。这两句在逻辑上是紧的：它知道**名词**，不一定知道**方法**。所以那句提示词的第三步（列工具）之后，**得追一句「现在就按这个做，别用表格替代」**。

**3. Thariq 的「砍掉 80% system prompt」不能直接搬。** 那是针对 Claude Code 团队模型和他们的 harness 做的实验。本机 `prompt-inject.md` 里有大量踩坑得来的约束（编码、路径、junction 三态那些），**那些是血换来的，别以「新模型更强」为理由删。** 要删也得先测。

**4. 第 7 步最容易假执行。** 「让它自己验」很容易退化成「它说它验了」。区别在有没有一个**你能亲手重跑**的命令或读数。没有就是假的。

**5. 原文里几个鼓动性案例我没核实。** 「可能帮助发现一颗新行星」「Sawe 跑出首个官方破两小时马拉松」「13.6% 的真人拒绝了危险操作而 auto mode 挡住 89%」这几条都是转述，当故事听可以，别当事实引用。
